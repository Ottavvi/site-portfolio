Case study

Pousada Lagoa Azul.

The website of a beachfront guesthouse: guests pick their dates, see the price of the stay with seasonal rates already applied, check availability and can pay the deposit via Pix, in Portuguese, English or Spanish.

The problem

Bookings by message, prices that change with the season.

At a small guesthouse, almost every booking starts on WhatsApp with the same questions: is there a room on these dates, how much is it, does the whole family fit. Prices aren't fixed: each room has a nightly rate and the seasons (school holidays, long weekends, New Year) add a percentage to each night.

The site had to answer that on its own, welcome tourists from abroad and stay easy to maintain: change a price, mark a date as booked or upload a photo without opening the code and with no monthly server cost .

The core feature

A booking simulation in seconds.

  1. Checks capacity. Four guests don't fit in the Double room, and the site says so before any calculation.
  2. Checks booked nights. If any date is already taken, it shows which ones and suggests the other rooms free for that period.
  3. Adds up night by night. Each night gets its own season's surcharge, including seasons that span New Year.
  4. Hands over a ready request. The button opens WhatsApp with the room, dates, guests and price already written.
Payment

A Pix deposit, with no middleman.

The Pix code is built right in the browser, following the Brazilian Central Bank's BR Code standard, with the deposit amount, a booking identifier and the CRC16 checksum banks require at the end. The QR Code comes from the same code, with the copy-and-paste version next to it.

With no payment gateway there are no per-transaction fees and no platform sign-up. The trade-off is that confirmation isn't automatic: the guesthouse checks the payment in its banking app and the guest sends the receipt on WhatsApp, through a button that opens the chat.

Technical decisions

A static site that builds itself.

No server or database to maintain. Content lives in files on GitHub and a script builds the final site on every change.

Template + data = site

The HTML is a template with placeholders; rooms, prices, seasons, booked dates, photos and contacts live in 9 JSON files, each text in Portuguese, English and Spanish. A Node.js script puts it all together and outputs the finished site.

An editing panel with no login server

The editing panel (Sveltia CMS) saves straight to the repository. Each save triggers GitHub Actions, which builds and deploys the site in about 1 minute , on free GitHub Pages hosting.

Photos optimized on the way

Every uploaded photo becomes WebP in two sizes, and the browser downloads the one that fits the screen. The cover gets its own versions and the social sharing image is generated from it. Processed photos are cached.

A typo can't take the site down

The script validates the data before publishing: a date in the wrong format, a missing photo, an unknown room. If something is wrong, publishing stops with a clear message and the live site stays on the previous version.

Details

Built for tourists and for phones.

  • Three languages that switch instantly, a dedicated address for each one ( ?lang=en ) and hreflang tags so Google shows the right version.
  • A fixed WhatsApp shortcut and a back-to-top button on mobile.
  • A gallery with an enlarged view and keyboard navigation.
  • Google Analytics only after the visitor consents, as Brazil's LGPD requires.
  • Its own error page, a sitemap and social sharing metadata.

What I learned

A good site is one that stays right after launch.

The first version had sample testimonials, packages and numbers to fill the layout. When the guesthouse's real information arrived, I removed everything that wasn't true, because a real business website can't promise what the place doesn't offer.

I also learned that the hard part isn't the screen, it's maintenance: separating content from code, validating what gets typed in and deploying automatically is what made the site maintainable. The next steps are the final photos and contacts and a custom domain.
