Estudo de caso

Pousada Lagoa Azul.

O site de uma pousada de frente para o mar: o hóspede escolhe as datas, vê o valor da estadia com as temporadas já calculadas, confere a disponibilidade e pode pagar o sinal via Pix, em português, inglês ou espanhol.

O problema

Reserva por mensagem, preço que muda com a época.

Numa pousada pequena, quase toda reserva começa no WhatsApp com as mesmas perguntas: tem vaga nessas datas, quanto fica, cabe a família toda. O preço não é fixo: cada quarto tem uma diária e as temporadas (férias, feriados, fim de ano) acrescentam uma porcentagem em cada noite.

O site precisava responder isso sozinho, receber turistas de fora do país e continuar fácil de manter: trocar um preço, marcar uma data ocupada ou subir uma foto sem abrir o código e sem custo mensal de servidor.

A parte principal

Simulação de reserva em segundos.

  1. Confere a capacidade. Quatro hóspedes não cabem no quarto Casal, e o site avisa antes de qualquer cálculo.
  2. Confere as noites ocupadas. Se alguma data já estiver reservada, mostra quais e sugere os outros quartos livres no período.
  3. Soma noite a noite. Cada noite recebe o acréscimo da sua temporada, inclusive as que atravessam a virada do ano.
  4. Leva o pedido pronto. O botão abre o WhatsApp com quarto, datas, hóspedes e valor já escritos.
Pagamento

Sinal via Pix, sem intermediário.

O código Pix é montado no próprio navegador, no padrão BR Code do Banco Central, com o valor do sinal, um identificador da reserva e o CRC16 que o banco exige no final. O QR Code sai do mesmo código, e o "copia e cola" fica ao lado.

Sem gateway de pagamento, não há taxa por transação nem cadastro em plataforma. Em troca, a confirmação não é automática: a pousada confere o pagamento no app do banco e o hóspede manda o comprovante pelo WhatsApp, num botão que já abre a conversa.

Decisões técnicas

Um site estático que se monta sozinho.

Nada de servidor nem banco de dados para manter. O conteúdo fica em arquivos no GitHub e um script monta o site final a cada alteração.

Modelo + dados = site

O HTML é um modelo com marcações; quartos, preços, temporadas, datas ocupadas, fotos e contatos ficam em 9 arquivos JSON, cada texto com versões em português, inglês e espanhol. Um script em Node.js junta tudo e gera o site pronto.

Painel sem servidor de login

O painel de edição (Sveltia CMS) salva direto no repositório. Cada salvamento dispara o GitHub Actions, que monta e publica o site em cerca de 1 minuto, com hospedagem gratuita no GitHub Pages.

Fotos otimizadas no caminho

Cada foto enviada vira WebP em dois tamanhos, e o navegador baixa o que cabe na tela. A capa ganha versões próprias e a imagem de compartilhamento é gerada a partir dela. Fotos já processadas ficam em cache.

Erro de digitação não derruba o site

O script confere os dados antes de publicar: data fora do formato, foto que não existe, quarto desconhecido. Se algo estiver errado, a publicação para com uma mensagem clara e o site no ar continua na versão anterior.

Detalhes

Feito para turista e para celular.

  • Três idiomas com troca na hora, endereço próprio para cada um (?lang=en) e marcações hreflang para o Google mostrar a versão certa.
  • Atalho fixo para o WhatsApp e botão de voltar ao topo no celular.
  • Galeria com visualização ampliada e navegação pelo teclado.
  • Google Analytics só depois do consentimento do visitante, como pede a LGPD.
  • Página de erro própria, sitemap e dados de compartilhamento para redes sociais.

O que aprendi

Site bom é o que continua certo depois de pronto.

A primeira versão tinha depoimentos, pacotes e números de exemplo para preencher o layout. Quando chegaram as informações reais da pousada, tirei tudo o que não era verdade, porque um site de negócio real não pode prometer o que o lugar não oferece.

Também aprendi que a parte difícil não é a tela, e sim a manutenção: separar conteúdo de código, validar o que é digitado e publicar sozinho foi o que tornou o site possível de manter. Os próximos passos são as fotos e os contatos definitivos e um domínio próprio.
