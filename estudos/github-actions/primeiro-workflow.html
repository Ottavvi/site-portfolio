Testes a cada push

Aula · 10 min

O workflow mais comum de todos: a cada push e pull request, instalar as dependências e rodar os testes. 

name: Testes

on:
  push:
    branches: [main]
  pull_request:

jobs:
  testes:
    runs-on: ubuntu-latest
    steps:
      - name: Baixar o código
        uses: actions/checkout@v4

      - name: Instalar o Node
        uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: npm

      - name: Instalar dependências
        run: npm ci

      - name: Rodar os testes
        run: npm test
  • A máquina começa vazia. O primeiro passo quase sempre é o actions/checkout, que baixa o repositório.
  • uses roda uma action pronta, escrita por outra pessoa (aqui, as oficiais do GitHub). O @v4 é a versão. with passa as opções dela.
  • run roda comandos no terminal da máquina, como você faria no seu computador.
  • cache: npm guarda os pacotes baixados entre uma execução e outra: as próximas ficam mais rápidas.
  • Se um passo falha (o comando termina com erro), os seguintes não rodam e o workflow fica vermelho.

Acompanhar

Na aba Actions do repositório aparece cada execução, com o log de cada passo. Num pull request, o resultado aparece no fim da página, e dá para exigir que ele passe antes de juntar (em Settings, Branches, regras de proteção).

Dica

Um selo no README mostra o estado para quem visita: ![Testes](https://github.com/USUARIO/REPO/actions/workflows/testes.yml/badge.svg).

Teste o que aprendeu

  1. Por que o primeiro passo costuma ser actions/checkout?

  2. Qual a diferença entre uses e run?

  3. O que acontece quando um passo falha?
