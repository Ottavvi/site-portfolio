CI, workflows e YAML

Aula · 10 min

Integração contínua (CI) é rodar automaticamente as verificações do projeto (testes, formatação, build) a cada mudança enviada. Entrega contínua (CD) vai um passo além e publica sozinho quando tudo passa. No GitHub, isso é feito pelo GitHub Actions, de graça para repositórios públicos.

Este site, por exemplo, tem um workflow que a cada push confere todos os links internos, a formatação e as notas do Lighthouse. Se algo quebra, o GitHub avisa por e-mail e marca o commit com um ✗ vermelho.

Onde fica

Workflows são arquivos .yml na pasta .github/workflows/ do repositório. Cada um diz quando rodar (on) e o que rodar (jobs, cada um com seus steps), numa máquina virtual que o GitHub liga só para isso (o runner).

YAML em 2 minutos

YAML é um formato de configuração feito para ser lido por gente. O editor desta trilha mostra como o GitHub entende o que você escreveu: 

# Comentários começam com #
name: Exemplo de YAML

on: push

jobs:
  ola:
    runs-on: ubuntu-latest
    steps:
      - name: Dizer olá
        run: echo "Olá, Actions!"
      - name: Várias linhas
        run: |
          echo "primeira linha"
          echo "segunda linha"
  • Chave: valor, com um espaço depois dos dois pontos.
  • A indentação (sempre com espaços, nunca tab) diz o que está dentro de quê.
  • Itens de lista começam com - . Em steps, cada passo é um item.
  • | começa um texto de várias linhas, que mantém as quebras.
  • Texto não precisa de aspas, a não ser que tenha caracteres especiais como : seguido de espaço ou comece com * ou {.
Dica

Errar a indentação é o erro número 1 em YAML. O editor desta trilha mostra o erro e a linha; no GitHub, a aba Actions mostra "Invalid workflow file".
