Matriz, cache e reaproveitamento

Aula · 13 min

Matriz

Uma matriz roda o mesmo job em várias combinações, em paralelo. Ideal para bibliotecas que precisam funcionar em várias versões do Node e sistemas: 

name: Matriz

on: [push, pull_request]

jobs:
  testes:
    strategy:
      fail-fast: false
      matrix:
        node: [20, 22]
        os: [ubuntu-latest, windows-latest]
    runs-on: ${{ matrix.os }}
    name: Node ${{ matrix.node }} em ${{ matrix.os }}
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: ${{ matrix.node }}
          cache: npm
      - run: npm ci
      - run: npm test

São 2 × 2 = 4 jobs. Com fail-fast: false, uma falha não cancela os outros, e você vê de uma vez quais combinações quebraram.

Cache e artefatos

  • Cache é para acelerar: pacotes baixados, builds intermediários. O cache: npm do setup-node cobre o caso comum; actions/cache serve para o resto.
  • Artefatos são resultados para guardar ou passar adiante: relatórios de teste, o build, prints de falhas. actions/upload-artifact e download-artifact. 
      - name: Guardar o relatório do Playwright
        if: failure()                      # só quando algo falhou
        uses: actions/upload-artifact@v4
        with:
          name: relatorio-playwright
          path: playwright-report/
          retention-days: 7

Não se repetir

  • Workflow reutilizável: um workflow com on: workflow_call pode ser chamado por outros, até de outros repositórios, com uses: dono/repo/.github/workflows/testes.yml@main.
  • Action composta: uma sequência de passos empacotada num action.yml, usada como qualquer action.

Segurança da cadeia

Uma action de terceiros roda com acesso ao seu código e aos segredos daquele job. Se o dono dela for invadido e mudar o que a tag @v4 aponta, o seu workflow passa a rodar o código novo. Para actions de fora das organizações oficiais, fixe pelo SHA do commit: 

      - uses: algum-dono/alguma-action@8f4b7f84864484a7bf31766abe9204da3cbe65b3   # v2.1.0

O Dependabot (um arquivo .github/dependabot.yml) abre pull requests sozinho quando sai versão nova das actions e dos pacotes do npm, mantendo tudo atualizado sem esforço.

Dica

Workflows disparados por pull_request de forks não recebem os segredos, de propósito. Cuidado com pull_request_target: ele recebe, e rodar o código do fork nele é uma brecha conhecida.
