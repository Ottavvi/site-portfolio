Segredos, permissões e deploy

Aula · 12 min

Segredos

Chaves de API, tokens de deploy e senhas nunca vão no arquivo do workflow. Elas ficam em Settings → Secrets and variables → Actions e entram no workflow por ${{ secrets.NOME }}. O GitHub esconde o valor nos logs (aparece ***): 

      - name: Avisar no Slack
        run: curl -X POST -d '{"text":"Publicado!"}' "$WEBHOOK"
        env:
          WEBHOOK: ${{ secrets.SLACK_WEBHOOK }}

Passe segredos por env em vez de escrever ${{ secrets.X }} direto no meio do comando: é mais seguro contra injeção de comandos.

GITHUB_TOKEN e permissões

Toda execução recebe um token automático, o GITHUB_TOKEN, que vale só para aquele repositório e expira no fim. O bloco permissions diz o que ele pode fazer. Comece pelo mínimo e libere só o necessário: 

permissions:
  contents: read     # ler o código
  pages: write       # publicar no GitHub Pages
  id-token: write    # provar a identidade do workflow para o Pages

Publicar no GitHub Pages

Para um site com build (Vite, React), o workflow gera os arquivos e entrega ao Pages. Em Settings → Pages, escolha "GitHub Actions" como origem: 

name: Publicar site

on:
  push:
    branches: [main]
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: npm
      - run: npm ci
      - run: npm run build
      - uses: actions/upload-pages-artifact@v3
        with:
          path: dist

  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.publicar.outputs.page_url }}
    steps:
      - id: publicar
        uses: actions/deploy-pages@v4
  • upload-pages-artifact empacota a pasta do build (dist) como um artefato, que passa de um job para o outro.
  • deploy-pages publica o artefato. O id do passo permite ler as saídas dele, como o endereço final.
  • environment registra o deploy, mostra o link no GitHub e permite exigir aprovação manual antes de publicar.
Dica

Um site sem build (só HTML, CSS e JS, como este portfólio) nem precisa de workflow: o GitHub Pages publica direto de uma branch.
