Manutenção automática

Aula · 11 min

Dependabot

O Dependabot abre pull requests sozinho quando sai versão nova de uma dependência. Não é um workflow: é um arquivo de configuração em .github/dependabot.yml: 

version: 2
updates:
  - package-ecosystem: npm
    directory: /
    schedule:
      interval: weekly
    groups:
      dependencias-de-desenvolvimento:
        dependency-type: development   # junta as de desenvolvimento num PR só
  - package-ecosystem: github-actions
    directory: /
    schedule:
      interval: monthly

Com os testes rodando em cada pull request, atualizar vira clicar em "Merge" quando fica verde.

Verificações agendadas

Algumas coisas quebram sem ninguém mexer no código: um link externo que saiu do ar, um certificado vencendo, uma API que mudou. Um workflow agendado confere de tempos em tempos: 

name: Links externos

on:
  schedule:
    - cron: '0 8 * * 1'      # segunda, 8h UTC
  workflow_dispatch:

jobs:
  links:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Conferir links
        uses: lycheeverse/lychee-action@v2
        with:
          args: --no-progress './**/*.html'
          fail: true
Dica

Workflows agendados em repositórios sem atividade por 60 dias são desativados pelo GitHub. Se parar de rodar, é isso: reative na aba Actions.

Workflows reutilizáveis

Vários repositórios com o mesmo processo de testes? Escreva uma vez, com on: workflow_call, e chame dos outros: 

# .github/workflows/testes-node.yml (no repositório "padroes")
on:
  workflow_call:
    inputs:
      node-version:
        type: string
        default: '22'

jobs:
  testes:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: ${{ inputs.node-version }}
      - run: npm ci
      - run: npm test

# em qualquer outro repositório:
jobs:
  testes:
    uses: minha-org/padroes/.github/workflows/testes-node.yml@main
    with:
      node-version: '20'
