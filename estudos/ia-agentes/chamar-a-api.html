Chamar a API

Aula · 13 min

Do servidor, nunca do navegador

A chamada leva a sua chave de API, que dá acesso à sua conta (e ao seu cartão). Ela nunca vai para o JavaScript do site: quem abrir o F12 copia. O front-end chama o seu back-end, e ele, com a chave numa variável de ambiente, chama a API (é o padrão da trilha de APIs e HTTP).

O pedido HTTP

Por baixo de tudo, é um POST com JSON:

// No servidor (Node 20+), com a chave em process.env.ANTHROPIC_API_KEY
const resposta = await fetch('https://api.anthropic.com/v1/messages', {
  method: 'POST',
  headers: {
    'content-type': 'application/json',
    'x-api-key': process.env.ANTHROPIC_API_KEY,
    'anthropic-version': '2026-10-21'
  },
  body: JSON.stringify({
    model: 'claude-opus-5-5',
    max_tokens: 1024,
    system: 'Você é o atendente virtual da pousada. Responda em português.',
    messages: [{ role: 'user', content: 'Qual o horário do check-in?' }]
  })
});
const mensagem = await resposta.json();
  • anthropic-version fixa a versão da API: mudanças que quebram compatibilidade só chegam quando você troca a data.
  • max_tokens é o limite da resposta. Se ela bater no limite, vem cortada.
  • messages é a conversa inteira, alternando user e assistant. A API não guarda nada entre pedidos: para continuar a conversa, você manda o histórico todo de novo.

A resposta

{
  "id": "msg_01...",
  "role": "assistant",
  "content": [
    { "type": "thinking", "thinking": "" },
    { "type": "text", "text": "O check-in é a partir das 14h." }
  ],
  "stop_reason": "end_turn",
  "usage": { "input_tokens": 41, "output_tokens": 12 }
}
  • content é uma lista de blocos. Além de text, podem vir blocos de raciocínio (thinking) e de uso de ferramentas (tool_use). Leia o texto filtrando pelo tipo, nunca com content[0].text.
  • stop_reason diz por que parou: end_turn (terminou), max_tokens (cortou), tool_use (quer usar uma ferramenta) ou refusal (recusou o pedido). Confira sempre antes de usar o conteúdo.
  • usage traz os tokens de entrada e saída: é com eles que se calcula o custo de cada chamada.

Com o SDK

Na prática, use o SDK oficial: ele cuida dos cabeçalhos, dos tipos e de tentar de novo em erros passageiros. 

// npm install @anthropic-ai/sdk
import Anthropic from '@anthropic-ai/sdk';

const client = new Anthropic(); // lê ANTHROPIC_API_KEY do ambiente

const mensagem = await client.messages.create({
  model: 'claude-opus-5-5',
  max_tokens: 1024,
  messages: [{ role: 'user', content: 'Qual o horário do check-in?' }]
});

for (const bloco of mensagem.content) {
  if (bloco.type === 'text') console.log(bloco.text);
}

Erros e limites

Os erros seguem o HTTP: 400 (pedido inválido), 401 (chave errada), 429 (limite de pedidos por minuto atingido), 500 e 529 (servidor sobrecarregado). Os 429 e 5xx são passageiros: tente de novo com espera crescente (o SDK já faz isso, duas vezes, por padrão). Para respostas longas, use streaming (client.messages.stream(...)): o texto vai chegando aos poucos e a tela não fica parada.

Dica

Prompts de sistema grandes e repetidos (um manual de 50 páginas, por exemplo) podem ir para o cache: marque o bloco com cache_control: { type: "ephemeral" } e as chamadas seguintes leem essa parte por uma fração do preço. Funciona por prefixo: deixe o que nunca muda no começo e o que muda (a pergunta, a data) no fim.
