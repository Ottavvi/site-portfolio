Prática: auditoria e acesso restrito

Aula · 35 min

Tarefas

  1. Crie a tabela auditoria (id, tabela, operacao, quando, usuario, antes jsonb, depois jsonb).
  2. Escreva uma função de gatilho genérica que registre INSERT, UPDATE e DELETE de qualquer tabela, guardando a linha antes e depois em JSONB.
  3. Ligue o gatilho em reservas. Altere o status de uma reserva e veja o registro.
  4. Crie o papel relatorios que só consegue ler a view reservas_detalhadas. Confira que ele não lê hospedes.
  5. Faça um pg_dump, restaure num banco novo e confira a contagem de reservas.

CREATE TABLE auditoria (
    id        bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    tabela    text NOT NULL,
    operacao  text NOT NULL,
    quando    timestamptz NOT NULL DEFAULT now(),
    usuario   text NOT NULL DEFAULT current_user,
    antes     jsonb,
    depois    jsonb
);

CREATE FUNCTION auditar() RETURNS trigger
LANGUAGE plpgsql AS $$
BEGIN
    INSERT INTO auditoria (tabela, operacao, antes, depois)
    VALUES (
        TG_TABLE_NAME,
        TG_OP,
        CASE WHEN TG_OP IN ('UPDATE', 'DELETE') THEN to_jsonb(OLD) END,
        CASE WHEN TG_OP IN ('INSERT', 'UPDATE') THEN to_jsonb(NEW) END
    );
    RETURN COALESCE(NEW, OLD);
END;
$$;

CREATE TRIGGER reservas_auditoria
AFTER INSERT OR UPDATE OR DELETE ON reservas
FOR EACH ROW EXECUTE FUNCTION auditar();

UPDATE reservas SET status = 'cancelada' WHERE id = 3;
SELECT operacao, antes->>'status' AS de, depois->>'status' AS para, usuario, quando FROM auditoria;

CREATE ROLE relatorios LOGIN PASSWORD 'troque-isto';
GRANT CONNECT ON DATABASE pousada TO relatorios;
GRANT USAGE ON SCHEMA public TO relatorios;
GRANT SELECT ON reservas_detalhadas TO relatorios;

SET ROLE relatorios;
SELECT count(*) FROM reservas_detalhadas;   -- funciona
SELECT * FROM hospedes;                      -- ERROR: permission denied for table hospedes
RESET ROLE;
pg_dump -Fc -d pousada -f pousada.dump
createdb pousada_restaurado
pg_restore -d pousada_restaurado pousada.dump
psql -d pousada_restaurado -c "SELECT count(*) FROM reservas"

TG_OP e TG_TABLE_NAME são variáveis que o Postgres preenche dentro de funções de gatilho, por isso a mesma função serve para qualquer tabela. A view funciona para o papel relatorios porque ela roda com as permissões de quem a criou. Backup que nunca foi restaurado não é backup: é esperança.
