Índices e EXPLAIN

Aula · 14 min

Sem índice, para achar as reservas de um hóspede o banco lê a tabela inteira (Seq Scan). Com um índice, ele vai direto às linhas, como o índice remissivo de um livro. 

EXPLAIN ANALYZE
SELECT * FROM reservas WHERE hospede_id = 42;
-- Seq Scan on reservas  (actual time=0.01..35.2 rows=8 loops=1)
--   Filter: (hospede_id = 42)
--   Rows Removed by Filter: 499992

CREATE INDEX reservas_hospede_idx ON reservas (hospede_id);

EXPLAIN ANALYZE
SELECT * FROM reservas WHERE hospede_id = 42;
-- Index Scan using reservas_hospede_idx on reservas  (actual time=0.02..0.05 rows=8 loops=1)

EXPLAIN mostra o plano que o banco escolheu; com ANALYZE, ele executa de verdade e mostra os tempos reais.

Que índices criar

  • Chaves primárias e UNIQUE já têm índice. Chaves estrangeiras não: crie para as colunas usadas em JOIN (reservas.hospede_id, reservas.quarto_id).
  • Colunas muito usadas em WHERE e ORDER BY.
  • Composto: (quarto_id, entrada) serve para filtrar por quarto e por quarto + data, mas não só por data. A ordem das colunas importa.
  • Parcial: CREATE INDEX ... WHERE status = 'pendente' indexa só o que interessa.
  • De expressão: CREATE INDEX ON hospedes (lower(email)) para buscas que usam lower(email) = ....
Dica

Índice não é de graça: ocupa espaço e deixa INSERT e UPDATE mais lentos. Crie a partir de consultas reais lentas (veja a extensão pg_stat_statements), não "por garantia" em toda coluna.

Teste o que aprendeu

  1. O Postgres cria índice automaticamente para chaves estrangeiras?

  2. Um índice em (quarto_id, entrada) ajuda num WHERE só com entrada?

  3. Qual a diferença entre EXPLAIN e EXPLAIN ANALYZE?
