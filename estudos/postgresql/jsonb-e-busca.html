JSONB e busca textual

Aula · 14 min

JSONB

O tipo jsonb guarda documentos JSON, consultáveis e indexáveis. Útil para dados de formato variável: preferências, respostas de APIs, atributos que mudam por produto. 

ALTER TABLE hospedes ADD COLUMN preferencias jsonb NOT NULL DEFAULT '{}';

UPDATE hospedes SET preferencias = '{"cama": "casal", "andar": "alto", "alergias": ["lactose"]}'
WHERE email = 'ana@exemplo.com';

SELECT nome, preferencias->>'cama' AS cama          -- ->> devolve texto; -> devolve jsonb
FROM hospedes
WHERE preferencias @> '{"andar": "alto"}';            -- @> "contém"

SELECT nome FROM hospedes WHERE preferencias->'alergias' ? 'lactose';

UPDATE hospedes SET preferencias = preferencias || '{"vegano": true}' WHERE id = 1;   -- mescla

CREATE INDEX hospedes_pref_idx ON hospedes USING gin (preferencias);   -- acelera @> e ?
Dica

JSONB é ótimo para o que varia; o que é fixo e consultado sempre (nome, e-mail, datas, valores) continua melhor em colunas normais, com tipos e restrições.

Busca textual

LIKE '%praia%' não usa índice comum e não entende plural nem acentos. A busca textual do Postgres entende o idioma: 

CREATE EXTENSION IF NOT EXISTS unaccent;

ALTER TABLE quartos ADD COLUMN descricao text;
ALTER TABLE quartos ADD COLUMN busca tsvector
    GENERATED ALWAYS AS (to_tsvector('portuguese', nome || ' ' || coalesce(descricao, ''))) STORED;
CREATE INDEX quartos_busca_idx ON quartos USING gin (busca);

SELECT nome, ts_rank(busca, consulta) AS relevancia
FROM quartos, websearch_to_tsquery('portuguese', 'vista mar varanda') AS consulta
WHERE busca @@ consulta
ORDER BY relevancia DESC;

O dicionário portuguese reduz as palavras ao radical: "varandas" encontra "varanda". websearch_to_tsquery aceita a sintaxe que as pessoas usam em buscadores (aspas, -palavra, or).

Teste o que aprendeu

  1. Qual a diferença entre -> e ->> no JSONB?

  2. Que tipo de índice acelera consultas @> em jsonb e busca textual?

  3. Por que a busca textual acha "varanda" ao procurar "varandas"?
