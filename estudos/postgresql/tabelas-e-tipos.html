Tabelas, tipos e restrições

Aula · 13 min

CREATE TABLE quartos (
    id          integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    nome        text NOT NULL UNIQUE,
    diaria      numeric(10, 2) NOT NULL CHECK (diaria > 0),
    capacidade  smallint NOT NULL DEFAULT 2 CHECK (capacidade BETWEEN 1 AND 10)
);

CREATE TABLE hospedes (
    id          bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    nome        text NOT NULL,
    email       text NOT NULL UNIQUE,
    criado_em   timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE reservas (
    id          bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    quarto_id   integer NOT NULL REFERENCES quartos(id),
    hospede_id  bigint NOT NULL REFERENCES hospedes(id) ON DELETE CASCADE,
    entrada     date NOT NULL,
    saida       date NOT NULL,
    status      text NOT NULL DEFAULT 'pendente' CHECK (status IN ('pendente', 'confirmada', 'cancelada')),
    CHECK (saida > entrada)
);

Escolher bem os tipos

  • GENERATED ALWAYS AS IDENTITY: o jeito atual de criar ids automáticos (no lugar do antigo serial).
  • text para textos. No Postgres, não há ganho em varchar(255); se quiser limite, use um CHECK (length(nome) <= 100).
  • numeric(10,2) para dinheiro: exato. Nunca float ou real.
  • timestamptz (com fuso) para momentos. O Postgres guarda em UTC e converte para o fuso da sessão.
  • date para datas sem hora, boolean, uuid, jsonb e arrays (text[]) também existem.
Dica

Coloque as regras no banco (NOT NULL, CHECK, UNIQUE, REFERENCES), não só na aplicação. O banco é a última linha de defesa: ele recusa dado inválido venha de onde vier, inclusive de um script feito às pressas.
