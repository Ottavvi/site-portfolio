Como deixei o portfólio três vezes mais rápido no celular

Fontes no próprio site e o Firebase carregado só quando precisa: de 4,6 s para 1,4 s até aparecer o primeiro texto.

  • Desempenho
  • Lighthouse
  • Firebase

Rodei o Lighthouse (a auditoria que vem no Chrome) no meu portfólio simulando um celular e levei um susto: nota 63 em desempenho, com 4,6 segundos até aparecer o primeiro texto na tela. Acessibilidade, boas práticas e SEO estavam em 100, então o problema era só velocidade.

O que estava pesando

  • As fontes do Google Fonts bloqueavam a página: o navegador esperava baixar o CSS das fontes, de outro servidor, antes de mostrar qualquer coisa.
  • O Firebase (mais de 100 KB) era baixado em todas as páginas, só para trocar o link "Entrar" por "Minha área" no menu. A maioria das visitas nem tem conta.

O que eu mudei

Baixei as duas fontes (só os caracteres latinos) e passei a servir do próprio site, com pré-carregamento. As duas usam a licença SIL Open Font License, que permite isso. 

<link rel="preload" href="fontes/inter-latin.woff2" as="font" type="font/woff2" crossorigin>

No caso do Firebase, a página agora só baixa o código se fizer diferença: nas páginas de conta ou se aquele navegador já entrou alguma vez. Para saber disso sem o Firebase, guardo uma marca no localStorage quando a pessoa faz login, e o import passa a ser dinâmico: 

if (localStorage.getItem('sessao') === '1') {
  const { auth } = await import('../firebase.js');
  // ...
}

O resultado

A nota foi de 63 para 96 e o primeiro texto passou a aparecer em 1,4 s. De bônus, as fontes deixaram de passar pelo Google, então o IP de quem visita não vai mais para lá.

O que aprendi

O que mais pesava não era o meu código, e sim coisas de fora carregadas sem necessidade. Antes de otimizar qualquer coisa, vale medir e olhar o que realmente está bloqueando a página.
