Scripts, variáveis e condições

Aula · 13 min

#!/usr/bin/env bash
# backup.sh: copia uma pasta para backups/ com a data no nome
set -euo pipefail

origem="${1:?Uso: ./backup.sh PASTA}"
destino="backups/$(basename "$origem")-$(date +%Y-%m-%d).tar.gz"

if [[ ! -d "$origem" ]]; then
  echo "Pasta não encontrada: $origem" >&2
  exit 1
fi

mkdir -p backups
tar -czf "$destino" "$origem"
echo "Backup criado: $destino ($(du -h "$destino" | cut -f1))"
chmod +x backup.sh     # dá permissão de execução
./backup.sh fotos
  • A primeira linha (shebang) diz qual programa roda o script.
  • set -euo pipefail: para no primeiro erro, trata variável não definida como erro e não ignora falhas no meio de um pipe. Comece todo script assim.
  • Variáveis: nome="valor" sem espaços em volta do =. Para ler: $nome.
  • $(comando) põe a saída de um comando no lugar.
  • $1, $2... são os argumentos; $# é quantos são; $@, todos.
  • ${1:?mensagem} para com a mensagem se o argumento faltar; ${1:-padrao} usa um valor padrão.
  • >&2 manda a mensagem para a saída de erros.
Dica

Coloque sempre as variáveis entre aspas duplas: "$arquivo". Sem aspas, um nome com espaço ("minhas fotos") vira dois argumentos, e um rm $arquivo pode apagar a coisa errada.

Testes no if

[[ -f arq ]]      # existe e é arquivo
[[ -d pasta ]]    # existe e é pasta
[[ -z "$x" ]]     # texto vazio
[[ "$a" == "$b" ]]
[[ $n -gt 10 ]]   # números: -eq -ne -lt -le -gt -ge
(( n > 10 ))      # ou aritmética direto
[[ -f a && -f b ]]

Teste o que aprendeu

  1. O que está errado em nome = "Ana"?

  2. O que faz set -e?

  3. Por que escrever "$arquivo" com aspas?
