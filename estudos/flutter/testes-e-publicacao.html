Dados locais, testes e publicação

Aula · 13 min

Guardar dados no aparelho

final prefs = await SharedPreferences.getInstance();
await prefs.setString('ultimo_hospede', 'Ana');
final nome = prefs.getString('ultimo_hospede') ?? '';

shared_preferences serve para preferências e pouca coisa. Para listas e dados estruturados, use um banco local como sqflite ou drift; para dados na nuvem, o Firebase (que tem integração oficial com o Flutter).

Testes

// test/contador_test.dart
import 'package:flutter_test/flutter_test.dart';

void main() {
  test('desconto acima de 200', () {
    final c = Carrinho()..adicionar('Vinho', 250);
    expect(c.total, 225);
  });

  testWidgets('botão + aumenta hóspedes', (tester) async {
    await tester.pumpWidget(const MaterialApp(home: Scaffold(body: Contador())));
    expect(find.text('1 hóspede(s)'), findsOneWidget);
    await tester.tap(find.byIcon(Icons.add));
    await tester.pump();                     // reconstrói depois do setState
    expect(find.text('2 hóspede(s)'), findsOneWidget);
  });
}

Publicar

flutter pub add --dev flutter_launcher_icons   # gera os ícones de todas as plataformas
flutter build appbundle    # Android (.aab) para a Google Play
flutter build ipa          # iOS (precisa de um Mac e conta de desenvolvedor Apple)
flutter build web          # site estático, dá para hospedar no GitHub Pages
  • Google Play: conta de desenvolvedor (taxa única), o app assinado com uma chave sua (guarde-a com cuidado: sem ela, você não publica atualizações), ficha da loja e política de privacidade.
  • App Store: Apple Developer Program (anual), Xcode e revisão da Apple.
  • Antes de publicar: troque o applicationId (Android) e o Bundle ID (iOS) de com.example para um seu, e teste em modo release (flutter run --release).
