Buscar dados

import 'dart:convert';
import 'package:http/http.dart' as http;

Future<List<Produto>> buscarProdutos() async {
  final resp = await http.get(Uri.parse('https://minha-api.com/produtos'));
  if (resp.statusCode != 200) throw Exception('Erro ${resp.statusCode}');
  final lista = jsonDecode(resp.body) as List;
  return lista.map((j) => Produto.fromJson(j)).toList();
}

Dica

Se o Future for criado dentro do build, cada reconstrução dispara uma nova requisição. Guarde-o numa variável do State.

Estado compartilhado com Riverpod

Quando várias telas precisam do mesmo dado (o carrinho, o usuário logado), passar por parâmetro fica inviável. O Riverpod é uma das soluções mais usadas: 

final produtosProvider = FutureProvider((ref) => buscarProdutos());

class CarrinhoNotifier extends Notifier<List<Produto>> {
  @override
  List<Produto> build() => [];
  void adicionar(Produto p) => state = [...state, p];   // sempre um estado novo
}
final carrinhoProvider = NotifierProvider<CarrinhoNotifier, List<Produto>>(CarrinhoNotifier.new);

class TelaLoja extends ConsumerWidget {
  const TelaLoja({super.key});
  @override
  Widget build(BuildContext context, WidgetRef ref) {
    final itens = ref.watch(carrinhoProvider).length;
    return ref.watch(produtosProvider).when(
          loading: () => const CircularProgressIndicator(),
          error: (e, _) => Text('Erro: $e'),
          data: (produtos) => ListView(children: [
            Text('$itens no carrinho'),
            for (final p in produtos)
              ListTile(
                title: Text(p.nome),
                onTap: () => ref.read(carrinhoProvider.notifier).adicionar(p),
              ),
          ]),
        );
  }
}
// main: runApp(const ProviderScope(child: MeuApp()));

ref.watch reconstrói o widget quando o valor muda; ref.read só lê (para usar em cliques). Outras opções populares são o Provider e o Bloc.

Teste o que aprendeu

  1. Por que não criar o Future dentro do build num FutureBuilder?

  2. Qual a diferença entre ref.watch e ref.read?

  3. Por que state = [...state, p] em vez de state.add(p)?
