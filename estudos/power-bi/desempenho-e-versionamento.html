Relatório lento?

Em Exibir, Analisador de desempenho, clique em Iniciar gravação e Atualizar visuais. Ele mostra quanto cada visual levou na consulta DAX, no desenho e em "Outros" (esperando os outros visuais). Os culpados de sempre:

  • Colunas demais: cada coluna carregada ocupa memória. Remova no Power Query tudo o que não é usado, principalmente textos longos e colunas de ID que não ligam nada.
  • Cardinalidade alta: uma coluna de data e hora com segundos tem milhões de valores diferentes. Separe data e hora, ou arredonde.
  • Colunas calculadas onde caberia uma medida, e medidas com iteradores sobre tabelas enormes.
  • Relacionamentos em ambas as direções e visuais demais numa página (cada um é uma consulta).
Dica

O DAX Studio e o Tabular Editor, ferramentas externas gratuitas que aparecem na guia Ferramentas Externas, mostram quanto cada coluna ocupa e o plano de cada consulta. São o próximo passo para quem leva desempenho a sério.

PBIP: o relatório no Git

O arquivo .pbix é binário: o Git não mostra o que mudou e duas pessoas não conseguem trabalhar juntas. O formato PBIP (Arquivo, Salvar como, Projeto do Power BI) salva o relatório como uma pasta de arquivos de texto: 

Vendas.pbip
Vendas.SemanticModel/
  definition/              ← tabelas, medidas e relacionamentos em TMDL (texto)
Vendas.Report/
  definition/pages/...     ← cada página e cada visual em JSON
.gitignore                 ← já vem pronto: deixa de fora o cache com os dados
  • O Git mostra exatamente qual medida ou visual mudou em cada commit.
  • Dá para revisar mudanças num pull request, como código.
  • Dá até para gerar relatórios por script: os painéis de exemplo deste portfólio foram criados assim, por código.

Ambientes

Em equipes, o relatório passa por etapas antes de chegar a quem usa: um workspace de desenvolvimento, um de teste e o de produção, com pipelines de implantação movendo de um para o outro e parâmetros trocando a fonte de dados em cada etapa.
