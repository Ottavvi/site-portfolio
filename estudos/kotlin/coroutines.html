Coroutines e Flow

Aula · 14 min

Apps não podem travar esperando a internet. As coroutines permitem escrever código assíncrono que parece sequencial. Adicione ao projeto org.jetbrains.kotlinx:kotlinx-coroutines-core (no Playground já vem). 

import kotlinx.coroutines.*

suspend fun buscarUsuario(): String {
    delay(1000)              // espera sem bloquear a thread
    return "Ana"
}

suspend fun buscarPedidos(): Int {
    delay(1500)
    return 7
}

fun main() = runBlocking {
    val inicio = System.currentTimeMillis()
    val usuario = async { buscarUsuario() }   // começa já
    val pedidos = async { buscarPedidos() }   // em paralelo
    println("${usuario.await()} tem ${pedidos.await()} pedidos")
    println("Levou ${System.currentTimeMillis() - inicio} ms")   // ~1500, não 2500
}
  • suspend marca uma função que pode pausar. Ela só pode ser chamada de outra suspend ou de dentro de uma coroutine.
  • launch inicia uma coroutine que não devolve valor; async devolve um Deferred, lido com await().
  • runBlocking é para o main e para testes. No Android, use os escopos prontos (viewModelScope, lifecycleScope), que cancelam tudo quando a tela fecha.

Flow: valores ao longo do tempo

import kotlinx.coroutines.flow.*

fun cronometro(): Flow<Int> = flow {
    for (s in 3 downTo 1) {
        emit(s)
        delay(1000)
    }
}

fun main() = runBlocking {
    cronometro()
        .map { "Faltam $it s" }
        .collect { println(it) }
}
Dica

Trocar de thread é com withContext(Dispatchers.IO) { ... } para disco e rede. A thread principal do Android (a da tela) nunca deve esperar nada lento.
