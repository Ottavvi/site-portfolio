ViewModel, rede e banco local

Aula · 15 min

A arquitetura recomendada pelo Google separa a tela (UI), quem guarda o estado da tela (ViewModel) e quem busca os dados (repositório, que fala com a rede e o banco). 

class ProdutosViewModel(private val repo: ProdutoRepository) : ViewModel() {
    private val _estado = MutableStateFlow<Estado>(Estado.Carregando)
    val estado: StateFlow<Estado> = _estado

    init { carregar() }

    fun carregar() = viewModelScope.launch {
        _estado.value = Estado.Carregando
        _estado.value = try {
            Estado.Sucesso(repo.listar())
        } catch (e: IOException) {
            Estado.Erro("Sem conexão")
        }
    }
}

@Composable
fun TelaProdutos(vm: ProdutosViewModel = viewModel()) {
    val estado by vm.estado.collectAsStateWithLifecycle()
    when (val e = estado) {
        Estado.Carregando -> CircularProgressIndicator()
        is Estado.Sucesso -> ListaProdutos(e.produtos) { }
        is Estado.Erro -> Text(e.mensagem)
    }
}

O ViewModel sobrevive a rotações de tela; as coroutines do viewModelScope são canceladas quando a tela fecha de vez.

interface LojaApi {

val api = Retrofit.Builder()
    .baseUrl("https://minha-api.com/")
    .addConverterFactory(Json.asConverterFactory("application/json".toMediaType()))
    .build()
    .create(LojaApi::class.java)

Lembre de pedir a permissão no AndroidManifest.xml: <uses-permission android:name="android.permission.INTERNET" />.

Banco local com Room

@Entity data class Tarefa(@PrimaryKey(autoGenerate = true) val id: Int = 0, val titulo: String, val feita: Boolean = false)

@Dao interface TarefaDao {
    @Query("SELECT * FROM Tarefa ORDER BY feita, titulo") fun todas(): Flow<List<Tarefa>>
    @Insert suspend fun inserir(t: Tarefa)
    @Update suspend fun atualizar(t: Tarefa)
}

Um DAO que devolve Flow emite a lista de novo a cada mudança na tabela: a tela se atualiza sozinha.
