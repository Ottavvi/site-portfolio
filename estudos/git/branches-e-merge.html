Branches, merge e conflitos

Aula · 13 min

Um branch (ramo) é uma linha de commits separada. A main fica sempre funcionando, e cada novidade nasce num ramo próprio. Se a ideia não der certo, é só apagar o ramo. 

git switch -c menu-novo      # cria o ramo e já entra nele
# ... edita, git add, git commit ...
git switch main              # volta para a main (os arquivos voltam junto)
git branch                   # lista os ramos; o * marca o atual

Juntar com merge

git switch main
git merge menu-novo          # traz os commits do ramo para a main
git branch -d menu-novo      # apaga o ramo, que não é mais necessário

Se a main não andou desde que o ramo nasceu, o Git só avança o ponteiro (fast-forward). Se os dois andaram, ele cria um commit de merge com dois pais.

Conflitos

Quando os dois ramos mudaram a mesma linha, o Git não adivinha qual vale e marca o arquivo: 

<<<<<<< HEAD
<h1>Pousada Lagoa Azul</h1>
=======
<h1>Bem-vindo à Lagoa Azul</h1>
>>>>>>> titulo-novo

Para resolver: edite o arquivo deixando a versão certa (pode ser uma mistura), apague as marcas <<<<<<<, ======= e >>>>>>>, e então: 

git add index.html
git commit                   # conclui o merge
# ou, para desistir: git merge --abort
Dica

O VS Code mostra os conflitos com botões "Aceitar atual", "Aceitar a que chega" e "Aceitar ambas". Conflito não é erro: é o Git pedindo para você decidir.

Guardar algo pela metade

Precisa trocar de ramo, mas o trabalho não está pronto para um commit? O git stash guarda as mudanças numa gaveta, e git stash pop as devolve.
