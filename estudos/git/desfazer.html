Desfazer: restore, revert, reset e reflog

Aula · 14 min

Quase tudo no Git tem volta. O segredo é escolher o comando certo para o tipo de arrependimento:

# Desfazer mudanças num arquivo que ainda não foram preparadas
git restore index.html

# Tirar da área de preparação (a mudança continua no arquivo)
git restore --staged index.html

# Corrigir a mensagem ou incluir um arquivo esquecido no ÚLTIMO commit (antes do push)
git add esquecido.css
git commit --amend -m "Mensagem certa"

# Desfazer um commit que JÁ foi enviado: cria um commit novo que faz o contrário
git revert a1b2c3d

# Voltar o ramo para um commit anterior (só em commits que ainda não foram enviados)
git reset --soft HEAD~1    # desfaz o commit, mantém as mudanças preparadas
git reset HEAD~1           # desfaz o commit, mantém as mudanças nos arquivos
git reset --hard HEAD~1    # desfaz o commit E apaga as mudanças

HEAD é o commit em que você está; HEAD~1 é o anterior a ele.

A regra de ouro

Não reescreva o que já foi enviado. reset, --amend e rebase criam commits novos no lugar dos antigos. Se alguém já baixou os antigos, os históricos divergem e vira confusão. Para o que já está no GitHub, use revert.

O reflog salva vidas

Fez um reset --hard errado? O Git guarda por uns 90 dias tudo por onde o HEAD passou: 

git reflog
# a1b2c3d HEAD@{0}: reset: moving to HEAD~1
# 9f8e7d6 HEAD@{1}: commit: Adiciona a galeria   <- o commit "perdido"
git reset --hard 9f8e7d6
Dica

O que nunca entrou num commit (nem no stash) o Git não tem como recuperar. Na dúvida antes de um comando perigoso, faça um commit ou um git stash: depois dá para desfazer.
