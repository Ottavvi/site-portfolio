O que é Git e o primeiro repositório

Aula · 9 min

Sem controle de versão, o histórico de um projeto vira uma pasta com site-final.zip, site-final-2.zip e site-agora-vai.zip. O Git resolve isso: ele guarda fotografias do projeto (os commits), cada uma com autor, data e uma mensagem dizendo o que mudou. Dá para voltar a qualquer uma, comparar duas e trabalhar em várias ideias ao mesmo tempo sem uma estragar a outra.

O GitHub é outra coisa: um site que hospeda repositórios Git na internet, para guardar uma cópia segura, colaborar e publicar (este portfólio está lá). O Git funciona sozinho, sem GitHub.

Instalar e configurar

No Windows, instale pelo git-scm.com (ele traz o Git Bash). No Mac, git no terminal oferece a instalação. Depois, diga quem você é: o nome e o e-mail vão em cada commit. 

git --version
git config --global user.name "Seu Nome"
git config --global user.email "voce@exemplo.com"
git config --global init.defaultBranch main

O primeiro repositório

mkdir meu-projeto
cd meu-projeto
git init          # cria a pasta oculta .git: é ali que o histórico mora
echo "# Meu projeto" > README.md
git status        # o Git vê um arquivo novo, ainda não acompanhado

Apagar a pasta .git apaga todo o histórico, mas deixa os arquivos. Por isso, não mexa nela à mão.

As três áreas

  • Pasta de trabalho: os arquivos como estão agora no disco.
  • Área de preparação (staging): o que vai entrar no próximo commit. Você escolhe com git add.
  • Repositório: os commits já gravados.
git add README.md               # prepara o arquivo
git commit -m "Cria o README"   # grava a fotografia
git log --oneline               # mostra o histórico, um commit por linha
Dica

A área de preparação existe para você separar as mudanças em commits com sentido. Mexeu no menu e corrigiu um erro de digitação no rodapé? Dois git add e dois commits deixam o histórico muito mais fácil de ler.
