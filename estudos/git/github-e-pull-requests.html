Intermediário · Módulo 2 · Ramos e GitHub

GitHub, push, pull e pull requests

Aula · 12 min

Remoto

Um remoto é uma cópia do repositório em outro lugar, normalmente no GitHub. Por convenção, o principal se chama origin. 

# Projeto que já existe no computador: crie um repositório vazio no GitHub e ligue os dois
git remote add origin https://github.com/seu-usuario/meu-projeto.git
git push -u origin main      # envia; o -u lembra a ligação para os próximos push

# Projeto que já está no GitHub: baixe tudo, com o histórico
git clone https://github.com/seu-usuario/meu-projeto.git

Sincronizar

git push        # envia os seus commits
git pull        # traz os commits novos do remoto (fetch + merge)
git fetch       # só baixa, sem juntar: dá para olhar antes com git log origin/main

Se alguém enviou commits antes de você, o push é recusado: faça git pull, resolva conflitos se houver, e envie de novo.

Dica

No login, o GitHub não aceita mais a senha da conta pelo terminal. O jeito mais simples é o Git Credential Manager (vem com o Git para Windows), que abre o navegador na primeira vez. Outra opção é o GitHub CLI: gh auth login.

Pull request

Em equipe, ninguém envia direto para a main. O fluxo é:

  1. Criar um ramo, fazer os commits e enviar: git push -u origin meu-ramo.
  2. No GitHub, abrir um pull request (PR): um pedido para juntar o ramo na main, com descrição do que mudou e por quê.
  3. Os colegas revisam e comentam linha por linha; o GitHub Actions roda os testes.
  4. Com tudo aprovado, clica-se em Merge, e o ramo pode ser apagado.
gh pr create --title "Adiciona página de contato" --body "Formulário com validação."
gh pr list
gh pr checkout 12     # baixa o PR de alguém para testar no seu computador

GitHub Pages

Para sites estáticos (HTML, CSS e JS), o GitHub publica de graça: em Settings → Pages, escolha o ramo main. O site fica em seu-usuario.github.io/nome-do-repositorio.
