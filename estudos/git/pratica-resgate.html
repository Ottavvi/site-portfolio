Prática: resgatar um histórico bagunçado

Aula · 20 min

Num repositório de teste, crie esta bagunça e depois conserte:

git switch -c galeria
echo "galeria" > galeria.html && git add . && git commit -m "teste"
echo "fotos" >> galeria.html && git commit -am "ajuste"
echo "legendas" >> galeria.html && git commit -am "agora vai"
  1. Transforme os três commits em um só, com a mensagem Adiciona a galeria de fotos.
  2. Você esqueceu o arquivo galeria.css. Crie-o e inclua-o no mesmo commit, sem criar outro.
  3. Rode git reset --hard HEAD~1 (sim, de propósito). A galeria sumiu. Recupere-a.
  4. Junte o ramo na main e marque a versão v1.0.0.
Ver a resposta 
# 1. Abre o editor com os 3 commits: troque "pick" por "squash" (ou "s") no 2º e no 3º,
#    salve e, na tela seguinte, deixe só a mensagem "Adiciona a galeria de fotos"
git rebase -i HEAD~3
#    Alternativa sem editor: volta 3 commits mantendo as mudanças preparadas e grava um só
git reset --soft HEAD~3
git commit -m "Adiciona a galeria de fotos"

# 2
echo ".galeria { display: grid; }" > galeria.css
git add galeria.css
git commit --amend --no-edit

# 3
git reset --hard HEAD~1
git reflog                 # ache a linha do commit "Adiciona a galeria de fotos"
git reset --hard HEAD@{1}  # (ou o código do commit que aparece no reflog)

# 4
git switch main
git merge galeria
git tag -a v1.0.0 -m "Primeira versão com galeria"

Tudo isso só é seguro porque o ramo ainda não tinha sido enviado. Se já estivesse no GitHub, os passos 1 e 2 exigiriam push --force-with-lease, e o certo seria combinar com a equipe antes.
