Banco de dados, variáveis de ambiente e segurança

Aula · 14 min

Banco de dados

Um array em memória some quando o servidor reinicia. Para guardar de verdade, use um banco. O SQLite é ótimo para começar (e para muitos projetos em produção): é um arquivo, sem servidor à parte. O Node 22 já traz um módulo para ele: 

import { DatabaseSync } from 'node:sqlite';

const db = new DatabaseSync('loja.db');
db.exec(`CREATE TABLE IF NOT EXISTS produtos (
  id INTEGER PRIMARY KEY, nome TEXT NOT NULL, preco REAL NOT NULL
)`);

const inserir = db.prepare('INSERT INTO produtos (nome, preco) VALUES (?, ?)');
const buscarPorNome = db.prepare('SELECT * FROM produtos WHERE nome LIKE ?');

inserir.run('Café em grãos', 62.9);
console.log(buscarPorNome.all('%café%'));

A trilha de SQLite deste site ensina a linguagem SQL com exemplos que rodam aqui mesmo.

Nunca monte SQL juntando texto

// NUNCA: se busca for  x' OR '1'='1  a consulta devolve tudo; com  '; DROP TABLE...  apaga
db.prepare(`SELECT * FROM usuarios WHERE email = '${busca}'`);

// SEMPRE: o ? é preenchido pelo banco, como valor, nunca como código
db.prepare('SELECT * FROM usuarios WHERE email = ?').get(busca);

Isso se chama injeção de SQL e é uma das falhas mais exploradas da web. Consultas parametrizadas (com ?) resolvem por completo.

Variáveis de ambiente

Senhas de banco, chaves de API e a porta mudam entre o seu computador e o servidor, e não podem ir para o Git. Elas ficam em variáveis de ambiente; em desenvolvimento, num arquivo .env que está no .gitignore: 

# .env (no .gitignore!)
PORT=3000
DATABASE_PATH=./loja.db
JWT_SECRET=troque-isto-por-um-texto-longo-e-aleatorio
// node --env-file=.env servidor.js   (o Node 20+ lê o arquivo sozinho)
const porta = Number(process.env.PORT ?? 3000);
if (!process.env.JWT_SECRET) {
  console.error('Falta JWT_SECRET no ambiente');
  process.exit(1);
}
Dica

Deixe no repositório um .env.example com os nomes das variáveis e valores falsos. Quem clonar o projeto sabe o que precisa configurar.

Senhas de usuários

Nunca guarde a senha em si. Guarde um hash lento com sal, feito para isso (scrypt, bcrypt ou argon2). O módulo node:crypto tem o scrypt: 

import { scrypt, randomBytes, timingSafeEqual } from 'node:crypto';
import { promisify } from 'node:util';
const scryptAsync = promisify(scrypt);

async function gerarHash(senha) {
  const sal = randomBytes(16).toString('hex');
  const hash = await scryptAsync(senha, sal, 64);
  return `${sal}:${hash.toString('hex')}`;
}

async function conferir(senha, guardado) {
  const [sal, hashHex] = guardado.split(':');
  const hash = await scryptAsync(senha, sal, 64);
  return timingSafeEqual(hash, Buffer.from(hashHex, 'hex'));
}

Outras proteções básicas de uma API: validar todo dado que chega (bibliotecas como zod ajudam), limitar tentativas de login (rate limit), responder erros sem expor detalhes internos e liberar o CORS só para os domínios do seu front-end.
