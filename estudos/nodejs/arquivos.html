Arquivos e caminhos

Aula · 12 min

Ler e escrever arquivos é uma das tarefas mais comuns em Node: gerar relatórios, processar CSVs, salvar configurações. Use a versão com Promises do módulo fs, que combina com await: 

import { readFile, writeFile, mkdir, readdir } from 'node:fs/promises';
import path from 'node:path';

const pasta = path.join(import.meta.dirname, 'dados');      // a pasta deste arquivo + /dados
await mkdir(pasta, { recursive: true });                    // cria se não existir

await writeFile(path.join(pasta, 'notas.txt'), 'primeira linha\n', 'utf8');
const texto = await readFile(path.join(pasta, 'notas.txt'), 'utf8');
console.log(texto);

console.log(await readdir(pasta));                          // nomes dos arquivos da pasta
  • Sempre informe 'utf8': sem ele, readFile devolve bytes (um Buffer), não texto.
  • Monte caminhos com path.join, nunca juntando texto com /: ele usa a barra certa no Windows e no Linux.
  • import.meta.dirname é a pasta do arquivo atual. Caminhos relativos soltos ('dados/x.txt') são relativos à pasta de onde você rodou o comando, o que pega muita gente de surpresa.

JSON em arquivo

async function lerJson(arquivo, padrao) {
  try {
    return JSON.parse(await readFile(arquivo, 'utf8'));
  } catch (erro) {
    if (erro.code === 'ENOENT') return padrao;   // o arquivo não existe (ainda)
    throw erro;                                   // outro problema: deixa estourar
  }
}

const config = await lerJson('config.json', { porta: 3000 });
await writeFile('config.json', JSON.stringify(config, null, 2));

Erros do sistema de arquivos têm um code: ENOENT (não existe), EACCES (sem permissão), EISDIR (é uma pasta). Trate os que você espera e deixe os outros aparecerem.

Por que tudo é assíncrono

O Node roda o seu JavaScript numa linha só. Enquanto espera o disco ou a rede, ele atende outras coisas: é assim que um único processo dá conta de milhares de conexões. Por isso as funções de entrada e saída devolvem Promises. As versões Sync (readFileSync) travam tudo enquanto esperam; servem para scripts pequenos, nunca dentro de um servidor. 

<script>
  // O mesmo princípio no navegador: três "leituras" de 300 ms em paralelo levam 300 ms, não 900
  const ler = (nome, ms) => new Promise(r => setTimeout(() => r(nome + ' lido'), ms));

  (async () => {
    let inicio = performance.now();
    await ler('a', 300); await ler('b', 300); await ler('c', 300);
    console.log('em sequência:', Math.round(performance.now() - inicio), 'ms');

    inicio = performance.now();
    const todos = await Promise.all([ler('a', 300), ler('b', 300), ler('c', 300)]);
    console.log(todos, 'em paralelo:', Math.round(performance.now() - inicio), 'ms');
  })();
</script>
Dica

Para arquivos grandes (um CSV de 2 GB), não leia tudo de uma vez: use createReadStream com o módulo readline para processar linha por linha, com memória constante.
