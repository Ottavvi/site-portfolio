Login: sessões, cookies e JWT

Aula · 13 min

HTTP não tem memória: cada pedido chega sozinho. Depois do login, a API precisa de um jeito de reconhecer a pessoa nos pedidos seguintes. Há dois caminhos principais.

Sessão com cookie

  1. A pessoa envia e-mail e senha. O servidor confere o hash da senha.
  2. O servidor cria uma sessão (um registro no banco ou em memória, com um id aleatório e longo) e devolve o id num cookie.
  3. O navegador manda o cookie sozinho em todo pedido seguinte; o servidor procura a sessão pelo id. 
res.setHeader('Set-Cookie',
  `sessao=${idAleatorio}; HttpOnly; Secure; SameSite=Lax; Path=/; Max-Age=${60 * 60 * 24 * 7}`);
  • HttpOnly: o JavaScript da página não consegue ler o cookie (protege contra roubo por XSS).
  • Secure: só vai por HTTPS.
  • SameSite=Lax: não é enviado em pedidos vindos de outros sites (protege contra CSRF na maioria dos casos).

Sair é apagar a sessão no servidor: a partir dali, o id não vale mais nada.

JWT

Um JWT (JSON Web Token) é um texto em três partes separadas por ponto: cabeçalho, conteúdo (payload) e assinatura. O servidor assina o conteúdo com uma chave secreta; ao receber o token de volta, confere a assinatura e confia no conteúdo sem consultar o banco. 

<pre id="saida"></pre>
<script>
  // Um JWT de exemplo (assinatura falsa). Repare: o conteúdo NÃO é criptografado, só codificado
  const token = 'eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.' +
    'eyJzdWIiOiI0MiIsIm5vbWUiOiJBbmEiLCJwYXBlbCI6ImFkbWluIiwiZXhwIjoxOTI0OTk1NjAwfQ.' +
    'assinatura-de-exemplo';

  const [cabecalho, conteudo] = token.split('.').map(parte => {
    try { return JSON.parse(atob(parte.replace(/-/g, '+').replace(/_/g, '/'))); } catch { return null; }
  });
  document.querySelector('#saida').textContent = JSON.stringify({ cabecalho, conteudo }, null, 2) +
    '\nExpira em: ' + new Date(conteudo.exp * 1000).toLocaleString('pt-BR');
</script>
  • Qualquer um lê o conteúdo de um JWT. Nunca coloque nele dados sensíveis.
  • Ninguém consegue alterar sem invalidar a assinatura. Por isso o servidor sempre verifica (com uma biblioteca como jose), e nunca apenas decodifica.
  • Como não há registro no servidor, um JWT não pode ser "desligado" antes de expirar: use validade curta (minutos) e um token de renovação guardado com cuidado.
Dica

Para um site com front-end e API no mesmo domínio, sessão com cookie HttpOnly costuma ser o caminho mais simples e seguro. JWT brilha quando vários serviços diferentes precisam confiar no mesmo login. E serviços prontos, como Firebase Auth (usado na área de estudos deste site), resolvem o login todo para você.
