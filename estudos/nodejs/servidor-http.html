Um servidor HTTP

Aula · 13 min

Com o módulo http

Um servidor recebe pedidos (método, endereço, cabeçalhos, corpo) e devolve respostas (status, cabeçalhos, corpo): 

// servidor.js
import { createServer } from 'node:http';

const produtos = [{ id: 1, nome: 'Café', preco: 62.9 }];

const servidor = createServer((req, res) => {
  const url = new URL(req.url, 'http://localhost');

  if (req.method === 'GET' && url.pathname === '/api/produtos') {
    res.writeHead(200, { 'Content-Type': 'application/json; charset=utf-8' });
    res.end(JSON.stringify(produtos));
    return;
  }

  res.writeHead(404, { 'Content-Type': 'application/json' });
  res.end(JSON.stringify({ erro: 'Não encontrado' }));
});

servidor.listen(3000, () => console.log('http://localhost:3000'));

Rode com node servidor.js e abra http://localhost:3000/api/produtos no navegador. Para parar, Ctrl+C no terminal.

Com o Express

O módulo http é a base, mas montar rotas, ler o corpo e tratar erros na mão dá trabalho. O Express é o framework mais usado para isso: 

import express from 'express';

const app = express();
app.use(express.json());           // lê o corpo JSON dos pedidos

const produtos = [{ id: 1, nome: 'Café', preco: 62.9 }];

app.get('/api/produtos', (req, res) => {
  res.json(produtos);
});

app.get('/api/produtos/:id', (req, res) => {
  const produto = produtos.find(p => p.id === Number(req.params.id));
  if (!produto) return res.status(404).json({ erro: 'Produto não encontrado' });
  res.json(produto);
});

app.post('/api/produtos', (req, res) => {
  const { nome, preco } = req.body;
  if (!nome || typeof preco !== 'number') {
    return res.status(400).json({ erro: 'Informe nome e preco (número)' });
  }
  const novo = { id: produtos.length + 1, nome, preco };
  produtos.push(novo);
  res.status(201).json(novo);
});

app.listen(3000);
  • :id na rota é um parâmetro: chega em req.params.id (sempre como texto).
  • ?busca=café chega em req.query.busca.
  • Os status contam o que aconteceu: 200 ok, 201 criado, 400 pedido inválido, 401 sem login, 404 não existe, 500 erro no servidor.
Dica

Para testar rotas POST sem escrever um front-end, use a extensão REST Client ou Thunder Client do VS Code, ou o comando curl -X POST -H "Content-Type: application/json" -d "{\"nome\":\"Chá\",\"preco\":22}" http://localhost:3000/api/produtos.

Como um roteador funciona por dentro

Um roteador compara o método e o caminho do pedido com uma lista de rotas. O próximo desafio é escrever um, e este exemplo mostra a parte mais curiosa: transformar /produtos/:id numa expressão regular: 

<script>
  function compilar(caminho) {
    const nomes = [];
    const regex = caminho.replace(/:(\w+)/g, (_, nome) => {
      nomes.push(nome);
      return '([^/]+)';
    });
    return { regex: new RegExp('^' + regex + '$'), nomes };
  }

  const rota = compilar('/lojas/:loja/produtos/:id');
  const achou = '/lojas/centro/produtos/42'.match(rota.regex);
  console.log(String(rota.regex), achou && Object.fromEntries(rota.nomes.map((n, i) => [n, achou[i + 1]])));
</script>

  1. Qual status responder quando um produto foi criado?

  2. Na rota /api/produtos/:id, onde chega o id?

  3. Para que serve app.use(express.json())?
