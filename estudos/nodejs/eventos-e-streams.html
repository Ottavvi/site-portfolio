Eventos e streams

Aula · 12 min

EventEmitter

Boa parte do Node é baseada em eventos: o servidor emite request, um arquivo emite data e end, um processo emite exit. A classe EventEmitter é a base disso, e você pode usá-la nos seus módulos: 

import { EventEmitter } from 'node:events';

class Pedidos extends EventEmitter {
  criar(pedido) {
    // ... salva no banco
    this.emit('criado', pedido);
  }
}

const pedidos = new Pedidos();
pedidos.on('criado', p => console.log('Enviar e-mail de confirmação para', p.email));
pedidos.on('criado', p => console.log('Atualizar estoque de', p.itens.length, 'itens'));
pedidos.once('criado', () => console.log('Primeiro pedido do dia!'));   // só na primeira vez
pedidos.criar({ email: 'ana@cafe.com', itens: [1, 2] });

Quem cria o pedido não precisa conhecer quem reage a ele: o e-mail e o estoque se inscrevem no evento. Esse desacoplamento é o padrão observador. O navegador tem a mesma ideia no EventTarget, que você já usa com addEventListener, e o próximo desafio é escrever um emissor do zero.

Streams: aos pedaços

Ler um CSV de 3 GB com readFile tenta pôr 3 GB na memória. Um stream entrega o arquivo em pedaços pequenos, e a memória usada fica constante: 

import { createReadStream } from 'node:fs';
import { createInterface } from 'node:readline';

const linhas = createInterface({ input: createReadStream('vendas-2026.csv', 'utf8') });
let total = 0;
for await (const linha of linhas) {
  const valor = Number(linha.split(';')[3]?.replace(',', '.'));
  if (!Number.isNaN(valor)) total += valor;
}
console.log('Total:', total.toFixed(2));

pipeline

Streams se encaixam como canos: ler, transformar, comprimir, gravar. pipeline liga tudo, cuida do controle de fluxo (não lê mais rápido do que consegue gravar) e fecha tudo se der erro no meio: 

import { pipeline } from 'node:stream/promises';
import { createReadStream, createWriteStream } from 'node:fs';
import { createGzip } from 'node:zlib';

await pipeline(
  createReadStream('relatorio.csv'),
  createGzip(),
  createWriteStream('relatorio.csv.gz')
);
Dica

Num servidor, a resposta (res) também é um stream. Para enviar um arquivo grande, use pipeline(createReadStream(arquivo), res) em vez de ler tudo para depois responder.
