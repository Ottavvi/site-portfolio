Desafio: clientes inativos

Desafio · 25 min

A loja vai fazer uma campanha para quem anda sumido. Considere que hoje é 2026-10-31 e que pedidos cancelados não contam. Escreva, nesta ordem:

  1. Uma consulta com nome e dias (dias inteiros desde o último pedido) de cada cliente que já comprou, do mais sumido para o mais recente (empates por nome).
  2. Uma consulta com o nome dos clientes que nunca compraram, por nome.
  3. Um CREATE VIEW vw_total_pedido com pedido_id e total (soma de quantidade × preço, 2 casas) de cada pedido.
  4. Uma consulta à view com pedido_id e total dos pedidos acima de 200, do maior para o menor.

O que o código precisa ter

  • 1ª consulta: nome e dias desde o último pedido, do mais sumido
  • 2ª consulta: quem nunca comprou (cancelado não conta)
  • A view vw_total_pedido existe, com pedido_id e total
  • 4ª consulta: pedidos acima de 200 pela view, do maior para o menor
Ver uma solução possível 
-- 1. Dias desde o último pedido (hoje é 2026-10-31)
SELECT c.nome,
       CAST(julianday('2026-10-31') - julianday(MAX(p.data)) AS INTEGER) AS dias
FROM clientes c
JOIN pedidos p ON p.cliente_id = c.id
WHERE p.status <> 'cancelado'
GROUP BY c.id, c.nome
ORDER BY dias DESC, c.nome;

-- 2. Clientes que nunca compraram
SELECT nome FROM clientes
WHERE id NOT IN (SELECT cliente_id FROM pedidos WHERE status <> 'cancelado')
ORDER BY nome;

-- 3. A view vw_total_pedido
CREATE VIEW vw_total_pedido AS
SELECT pedido_id, ROUND(SUM(quantidade * preco), 2) AS total
FROM itens
GROUP BY pedido_id;

-- 4. Pedidos acima de 200, pela view
SELECT pedido_id, total FROM vw_total_pedido
WHERE total > 200
ORDER BY total DESC;
