Subconsultas, CTEs e janelas

Aula · 14 min

Subconsultas

Uma consulta pode usar o resultado de outra. "Quais produtos custam mais que a média?":

SELECT nome, preco FROM produtos
WHERE preco > (SELECT AVG(preco) FROM produtos)
ORDER BY preco DESC;

Com IN, a subconsulta devolve uma lista. "Quais produtos nunca foram vendidos?":

SELECT nome FROM produtos
WHERE id NOT IN (SELECT produto_id FROM itens);

CTE: dar nome a um passo

Quando a consulta fica longa, WITH cria uma tabela temporária com nome, que existe só durante a consulta. Fica parecido com dividir um problema em variáveis: 

WITH total_por_pedido AS (
  SELECT pedido_id, SUM(quantidade * preco) AS total
  FROM itens
  GROUP BY pedido_id
)
SELECT ROUND(AVG(total), 2) AS ticket_medio, ROUND(MAX(total), 2) AS maior_pedido
FROM total_por_pedido;

CASE: decisões dentro da consulta

SELECT nome, estoque,
  CASE
    WHEN estoque = 0 THEN 'esgotado'
    WHEN estoque < 10 THEN 'acabando'
    ELSE 'ok'
  END AS situacao
FROM produtos
ORDER BY estoque;

Funções de janela

Uma agregação com GROUP BY junta as linhas. Uma função de janela calcula sobre um grupo sem juntar: cada linha continua lá, com o cálculo ao lado. É assim que se faz ranking e total acumulado: 

SELECT categoria, nome, preco,
  RANK() OVER (PARTITION BY categoria ORDER BY preco DESC) AS posicao_na_categoria,
  ROUND(AVG(preco) OVER (PARTITION BY categoria), 2) AS media_da_categoria
FROM produtos
ORDER BY categoria, posicao_na_categoria;

PARTITION BY separa os grupos e o ORDER BY de dentro do OVER define a ordem da conta. Para um total acumulado, some com SUM(...) OVER (ORDER BY data).

Dica

Para descobrir por que uma consulta está lenta, ponha EXPLAIN QUERY PLAN antes dela. Se aparecer SCAN numa tabela grande filtrada por uma coluna, um índice (CREATE INDEX) naquela coluna costuma resolver.

  2. Qual a diferença entre GROUP BY e uma função de janela?
