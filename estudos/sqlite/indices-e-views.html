Índices, views e EXPLAIN

Aula · 12 min

Índices

Sem índice, para achar os pedidos do cliente 4 o banco lê a tabela inteira (um scan). Com milhões de linhas, isso demora. Um índice é como o índice remissivo de um livro: uma lista ordenada que leva direto às linhas certas. 

EXPLAIN QUERY PLAN SELECT * FROM pedidos WHERE cliente_id = 4;

CREATE INDEX idx_pedidos_cliente ON pedidos(cliente_id);

EXPLAIN QUERY PLAN SELECT * FROM pedidos WHERE cliente_id = 4;

Compare as duas linhas do plano: antes, SCAN pedidos; depois, SEARCH pedidos USING INDEX idx_pedidos_cliente.

  • Crie índices nas colunas usadas em WHERE, em JOIN (as chaves estrangeiras!) e em ORDER BY de consultas frequentes.
  • Índices têm custo: ocupam espaço e deixam INSERT e UPDATE um pouco mais lentos. Não crie um para cada coluna.
  • CREATE UNIQUE INDEX também garante que não haja repetição (e-mail único, por exemplo).
  • Índice composto (cliente_id, data) atende filtros por cliente e por cliente + data, nessa ordem.

Views

Uma view é uma consulta guardada com nome, usada como se fosse uma tabela. Ótima para não repetir JOINs complicados e para dar a quem faz relatórios uma visão pronta: 

CREATE VIEW vw_vendas AS
SELECT p.id AS pedido, p.data, c.nome AS cliente, pr.nome AS produto, pr.categoria,
       i.quantidade, i.quantidade * i.preco AS valor
FROM itens i
JOIN pedidos p   ON p.id = i.pedido_id
JOIN clientes c  ON c.id = p.cliente_id
JOIN produtos pr ON pr.id = i.produto_id
WHERE p.status <> 'cancelado';

SELECT categoria, ROUND(SUM(valor), 2) AS total FROM vw_vendas GROUP BY categoria;
SELECT cliente, COUNT(DISTINCT pedido) AS pedidos FROM vw_vendas GROUP BY cliente ORDER BY pedidos DESC;

A view não guarda dados: a consulta roda de novo a cada uso, sempre com os dados atuais.

Dica

Ferramentas de BI, como o Power BI, conseguem ler views direto do banco. Uma view bem feita é um ótimo "contrato" entre quem cuida do banco e quem faz os relatórios.
