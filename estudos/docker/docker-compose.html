Docker Compose: vários serviços juntos

Aula · 13 min

Uma aplicação de verdade tem várias partes: a API, o banco, talvez um cache. Em vez de vários docker run compridos, o Compose descreve tudo num arquivo compose.yaml, e um comando sobe o conjunto: 

# compose.yaml
services:
  api:
    build: .
    ports:
      - "3000:3000"
    environment:
      DATABASE_URL: postgres://postgres:${DB_SENHA}@banco:5432/loja
    depends_on:
      banco:
        condition: service_healthy
    restart: unless-stopped

  banco:
    image: postgres:17
    environment:
      POSTGRES_PASSWORD: ${DB_SENHA}
      POSTGRES_DB: loja
    volumes:
      - dados-banco:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U postgres"]
      interval: 5s
      retries: 10

volumes:
  dados-banco:
  • Cada serviço é um contêiner. O Compose cria uma rede para eles, e um encontra o outro pelo nome do serviço: a API acessa o banco no endereço banco, não em localhost.
  • ${DB_SENHA} vem de um arquivo .env na mesma pasta (que fica fora do Git).
  • depends_on com service_healthy espera o banco estar pronto (o healthcheck passar), não só ligado.
  • restart: unless-stopped religa o serviço se ele cair.
docker compose up -d --build   # constrói e sobe tudo em segundo plano
docker compose ps              # o estado de cada serviço
docker compose logs -f api     # os logs de um serviço
docker compose exec banco psql -U postgres -d loja
docker compose down            # para e apaga os contêineres (o volume fica)
docker compose down -v         # ...e apaga também os volumes (os dados!)
Dica

Dentro de um contêiner, localhost é o próprio contêiner. Esse é o erro mais comum de quem começa com Compose: a API tentando falar com o banco em localhost:5432. Use o nome do serviço.

  1. No Compose, como a API acessa o serviço banco?

  2. O que depends_on com condition: service_healthy garante?
