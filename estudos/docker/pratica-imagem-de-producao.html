Prática: a imagem de produção

Aula · 25 min

Use um projeto React ou Vite qualquer (npm create vite@latest meu-site serve).

  1. Escreva um Dockerfile em dois estágios: o primeiro roda npm ci e npm run build; o segundo, a partir de nginx:1.27-alpine, só serve a pasta dist.
  2. Construa, rode na porta 8080 e compare o tamanho da imagem com a node:22-slim.
  3. Rode a varredura de vulnerabilidades na imagem.
  4. Escreva o workflow que publica a imagem no GHCR a cada push na main, marcada com o sha do commit.
Ver a resposta 
# 1. Dockerfile
FROM node:22-slim AS build
WORKDIR /app
COPY package.json package-lock.json ./
RUN npm ci
COPY . .
RUN npm run build

FROM nginx:1.27-alpine
COPY --from=build /app/dist /usr/share/nginx/html
EXPOSE 80

# 2
docker build -t meu-site:1.0 .
docker run -d -p 8080:80 --name meu-site meu-site:1.0
docker image ls     # meu-site fica na casa dos 50 MB; node:22-slim passa de 200 MB

# 3
docker scout cves meu-site:1.0

O passo 4 é o workflow da aula anterior, com permissions: packages: write, o docker/login-action e o docker/build-push-action com tags: ghcr.io/${{ github.repository }}:${{ github.sha }}.

A imagem do nginx já roda os processos que atendem pedidos com um usuário sem privilégios. Para ir além, existe a variante nginxinc/nginx-unprivileged, que nem o processo principal roda como root (ela usa a porta 8080 em vez da 80).
