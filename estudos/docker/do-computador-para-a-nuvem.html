Do computador para a nuvem

Aula · 12 min

Publicar a imagem

Para outro computador rodar a sua imagem, ela vai para um registro. O do GitHub (ghcr.io) fica junto do código: 

docker tag minha-api:1.0 ghcr.io/seu-usuario/minha-api:1.0
docker login ghcr.io       # usuário do GitHub e um token com permissão de pacotes
docker push ghcr.io/seu-usuario/minha-api:1.0

Build automático

Melhor ainda: o GitHub Actions constrói e publica a cada push na main, sem passo manual (veja a trilha de GitHub Actions): 

# .github/workflows/imagem.yml
name: Imagem
on:
  push:
    branches: [main]
permissions:
  contents: read
  packages: write
jobs:
  publicar:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: docker/login-action@v3
        with:
          registry: ghcr.io
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}
      - uses: docker/build-push-action@v6
        with:
          push: true
          tags: ghcr.io/${{ github.repository }}:${{ github.sha }}

Marcar a imagem com o código do commit (github.sha) deixa claro qual versão está rodando e facilita voltar para a anterior.

Onde rodar

  • Plataformas que rodam contêineres (Google Cloud Run, Render, Fly.io, Railway, Azure Container Apps): você aponta a imagem e elas cuidam de HTTPS, escala e reinício. Algumas desligam o contêiner sem uso e cobram só pelo tempo ligado.
  • Um servidor próprio (uma VPS) com Docker e o mesmo compose.yaml: mais controle e custo fixo, mas atualizações, backups e segurança ficam com você.
  • Kubernetes: para muitos serviços e equipes grandes. Para um projeto pequeno, costuma ser complexidade demais.

Em produção

  • Logs vão para a saída padrão (console.log); a plataforma recolhe.
  • Uma rota de saúde (/saude) para a plataforma saber se o contêiner está bem e reiniciá-lo se não estiver.
  • Banco de dados gerenciado (o da própria nuvem), com backup automático, costuma ser melhor que um contêiner de banco cuidado à mão.
Dica

Sites estáticos (como este portfólio) não precisam de Docker: o GitHub Pages, a Netlify ou a Vercel publicam a pasta direto. Docker brilha quando há um servidor rodando: uma API, um back-end com banco, um serviço com dependências do sistema.
