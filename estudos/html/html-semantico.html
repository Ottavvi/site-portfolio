Módulo 2 · Estrutura e semântica

HTML semântico

Aula · 9 min

Dá para montar uma página inteira só com <div>, um elemento genérico, sem significado. Mas o navegador, o Google e os leitores de tela entendem muito melhor a página quando cada parte usa o elemento que diz o que ela é. Isso é HTML semântico.

Os elementos de estrutura

  • <header>: o cabeçalho, com logo e, muitas vezes, o menu.
  • <nav>: um bloco de links de navegação.
  • <main>: o conteúdo principal. Só um por página.
  • <section>: uma seção temática, normalmente com um título.
  • <article>: um conteúdo que faz sentido sozinho, como um post, uma notícia ou um produto.
  • <aside>: um conteúdo complementar, como uma barra lateral.
  • <footer>: o rodapé, da página ou de um artigo.
<header>
  <strong>Meu Blog</strong>
  <nav>
    <a href="#">Início</a>
    <a href="#">Sobre</a>
  </nav>
</header>

<main>
  <article>
    <h1>Aprendendo HTML semântico</h1>
    <p>Hoje eu aprendi a estruturar uma página...</p>
  </article>

  <aside>
    <h2>Posts recentes</h2>
    <ul>
      <li><a href="#">Meu primeiro site</a></li>
    </ul>
  </aside>
</main>

<footer>
  <p>Feito por mim, 2026.</p>
</footer>

E a div, quando usar?

A <div> continua útil quando nenhum elemento semântico se encaixa, normalmente para agrupar coisas só por causa do layout. O mesmo vale para o <span>, a versão para pedaços de texto dentro de uma linha.

Dica

Uma boa pergunta: "se eu tirasse todo o CSS, essa parte ainda faria sentido com esse nome?". Se sim, provavelmente existe um elemento semântico para ela.

Por que vale a pena

  • Leitores de tela deixam a pessoa pular direto para o main ou para a navegação.
  • O Google entende melhor o que é conteúdo principal e o que é menu ou rodapé.
  • O código fica mais fácil de ler: </nav> diz muito mais que o quinto </div> seguido.

Teste o que aprendeu

  1. Quantos <main> uma página deve ter?

  2. Qual elemento combina com um post de blog, que faz sentido sozinho?

  3. Quando faz sentido usar <div>?
