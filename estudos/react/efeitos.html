Efeitos com useEffect

Aula · 14 min

Um componente deve só calcular o que mostrar. Tudo o que mexe com o mundo de fora (o título da aba, um timer, buscar dados, o localStorage) vai num efeito, que roda depois de o React atualizar a tela.

useEffect e as dependências

import { useState, useEffect } from 'react';
import { createRoot } from 'react-dom/client';

function App() {
  const [mensagens, setMensagens] = useState(0);

  useEffect(() => {
    document.title = mensagens ? `(${mensagens}) Caixa de entrada` : 'Caixa de entrada';
    console.log('efeito rodou com', mensagens);
  }, [mensagens]);

  return <button onClick={() => setMensagens(m => m + 1)}>Nova mensagem ({mensagens})</button>;
}

createRoot(document.getElementById('root')).render(<App />);

O array no fim são as dependências: o efeito roda depois do primeiro desenho e de novo sempre que algum desses valores mudar. Com [], roda só uma vez. Sem o array, roda depois de todo desenho (quase nunca é o que você quer).

Limpeza

Se o efeito liga algo (um timer, um evento na janela), ele devolve uma função que desliga. O React chama essa limpeza antes de rodar o efeito de novo e quando o componente sai da tela: 

import { useState, useEffect } from 'react';
import { createRoot } from 'react-dom/client';

function Relogio() {
  const [agora, setAgora] = useState(new Date());
  useEffect(() => {
    const id = setInterval(() => setAgora(new Date()), 1000);
    return () => clearInterval(id);
  }, []);
  return <p>{agora.toLocaleTimeString('pt-BR')}</p>;
}

function App() {
  const [visivel, setVisivel] = useState(true);
  return (
    <>
      <button onClick={() => setVisivel(v => !v)}>{visivel ? 'Esconder' : 'Mostrar'} relógio</button>
      {visivel && <Relogio />}
    </>
  );
}

createRoot(document.getElementById('root')).render(<App />);

Sem o clearInterval, cada vez que o relógio aparecesse e sumisse, um timer a mais ficaria rodando para sempre.

Buscar dados

function Usuario({ id }) {
  const [usuario, setUsuario] = useState(null);
  const [erro, setErro] = useState(null);

  useEffect(() => {
    const controle = new AbortController();
    setUsuario(null);
    fetch(`/api/usuarios/${id}`, { signal: controle.signal })
      .then(r => (r.ok ? r.json() : Promise.reject(new Error('HTTP ' + r.status))))
      .then(setUsuario)
      .catch(e => e.name !== 'AbortError' && setErro(e));
    return () => controle.abort();   // id mudou antes de chegar? cancela a busca velha
  }, [id]);

  if (erro) return <p>Não deu para carregar.</p>;
  if (!usuario) return <p>Carregando…</p>;
  return <h2>{usuario.nome}</h2>;
}
Dica

Em desenvolvimento, o <StrictMode> do React roda cada efeito duas vezes (liga, limpa e liga de novo) de propósito, para mostrar efeitos sem limpeza. Se algo acontece em dobro só no modo de desenvolvimento, falta a função de limpeza. Em projetos maiores, bibliotecas como TanStack Query cuidam de buscar dados, cache e recarregamento.

  1. Com useEffect(fn, []), quando fn roda?

  2. Para que serve a função devolvida pelo efeito?

  3. Por que o AbortController na busca de dados?
