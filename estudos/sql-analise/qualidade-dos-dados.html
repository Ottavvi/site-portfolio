Qualidade dos dados

Aula · 12 min

Uma análise é tão boa quanto os dados. Antes de mostrar um número, vale rodar algumas checagens. Todas seguem a mesma ideia: uma consulta que deveria voltar vazia. Se voltar algo, há um problema.

Órfãos

Linhas que apontam para algo que não existe (um item de um pedido apagado, um pedido de um cliente que não está na tabela): 

SELECT i.*
FROM itens i
LEFT JOIN pedidos p ON p.id = i.pedido_id
WHERE p.id IS NULL;

Duplicados

-- O mesmo produto duas vezes no mesmo pedido?
SELECT pedido_id, produto_id, COUNT(*) AS vezes
FROM itens
GROUP BY pedido_id, produto_id
HAVING COUNT(*) > 1;

Valores impossíveis e vazios

SELECT 'quantidade <= 0' AS problema, COUNT(*) AS linhas FROM itens WHERE quantidade <= 0
UNION ALL
SELECT 'preço negativo', COUNT(*) FROM produtos WHERE preco < 0
UNION ALL
SELECT 'cliente sem estado', COUNT(*) FROM clientes WHERE estado IS NULL OR TRIM(estado) = ''
UNION ALL
SELECT 'pedido no futuro', COUNT(*) FROM pedidos WHERE data > '2026-10-31';

Conferir os totais

A soma das partes tem que bater com o todo. Se o faturamento por categoria não somar o faturamento geral, algum JOIN está perdendo ou duplicando linhas: 

SELECT
  (SELECT ROUND(SUM(quantidade * preco), 2) FROM itens) AS total_geral,
  (SELECT ROUND(SUM(t), 2) FROM (
     SELECT SUM(i.quantidade * i.preco) AS t
     FROM itens i JOIN produtos pr ON pr.id = i.produto_id
     GROUP BY pr.categoria)) AS soma_das_categorias;
Dica

Guarde essas checagens num arquivo e rode sempre que os dados forem atualizados. É o equivalente dos testes automáticos para quem trabalha com dados, e ferramentas como o dbt são construídas exatamente em cima dessa ideia.
