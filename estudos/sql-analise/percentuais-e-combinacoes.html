Percentuais, UNION e EXISTS

Aula · 12 min

Percentual do total

"Quanto cada categoria representa do faturamento?" pede o total de cada grupo dividido pelo total geral. Uma função de janela sem PARTITION BY soma tudo, sem juntar as linhas: 

SELECT pr.categoria,
  ROUND(SUM(i.quantidade * i.preco), 2) AS total,
  ROUND(100.0 * SUM(i.quantidade * i.preco) / SUM(SUM(i.quantidade * i.preco)) OVER (), 1) AS pct
FROM itens i
JOIN produtos pr ON pr.id = i.produto_id
GROUP BY pr.categoria
ORDER BY total DESC;

SUM(SUM(...)) OVER () parece estranho, mas lê-se assim: a soma de dentro é a do grupo (por causa do GROUP BY); a de fora soma esses totais de todos os grupos.

Dica

Divisão de inteiros no SQLite descarta os decimais: 1 / 3 dá 0. Multiplique por 100.0 (com ponto) antes de dividir, e o resultado vira decimal.

UNION: empilhar resultados

UNION ALL põe um resultado embaixo do outro (as colunas precisam bater). UNION faz o mesmo e tira as linhas repetidas. Útil para montar uma tabela de resumo com linhas de naturezas diferentes: 

SELECT 'Clientes' AS indicador, COUNT(*) AS valor FROM clientes
UNION ALL
SELECT 'Produtos', COUNT(*) FROM produtos
UNION ALL
SELECT 'Pedidos entregues', COUNT(*) FROM pedidos WHERE status = 'entregue';

EXISTS: existe pelo menos um?

"Quais clientes já compraram algum Utensílio?" não quer saber quantos, só se existe. EXISTS para de procurar no primeiro que achar, e não duplica clientes como um JOIN faria: 

SELECT c.nome
FROM clientes c
WHERE EXISTS (
  SELECT 1
  FROM pedidos p
  JOIN itens i     ON i.pedido_id = p.id
  JOIN produtos pr ON pr.id = i.produto_id
  WHERE p.cliente_id = c.id AND pr.categoria = 'Utensílios'
)
ORDER BY c.nome;

NOT EXISTS faz o contrário e, diferente de NOT IN, não se confunde quando a subconsulta tem NULL.
