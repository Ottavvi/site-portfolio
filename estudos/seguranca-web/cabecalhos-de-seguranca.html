Cabeçalhos de segurança e CSP

Aula · 14 min

Alguns cabeçalhos HTTP mandam o navegador ativar proteções. São poucas linhas na configuração do servidor (ou da hospedagem) e fecham classes inteiras de ataque.

HTTPS e HSTS

HTTPS é obrigatório: sem ele, qualquer um na mesma rede Wi-Fi lê e altera o que trafega. O HSTS manda o navegador nunca mais tentar HTTP naquele domínio: 

Strict-Transport-Security: max-age=31536000; includeSubDomains

Content-Security-Policy (CSP)

A CSP diz de onde a página pode carregar scripts, estilos, imagens e para onde pode fazer pedidos. Se um XSS conseguir injetar um <script>, o navegador recusa rodar, porque ele não está na lista. É a segunda camada contra o XSS. 

Content-Security-Policy:
  default-src 'self';
  script-src 'self' https://cdn.jsdelivr.net;
  img-src 'self' data: https:;
  connect-src 'self' https://api.exemplo.com;
  frame-ancestors 'none';
  object-src 'none';
  base-uri 'self'
  • default-src 'self': por padrão, só do próprio domínio.
  • Evite 'unsafe-inline' em script-src: ele libera justamente o tipo de script que um XSS injeta. Mova o JavaScript dos atributos onclick e das tags <script> para arquivos.
  • frame-ancestors 'none': ninguém pode pôr seu site num iframe (protege contra o clickjacking, em que seu botão aparece escondido sob outra página).
  • Comece com Content-Security-Policy-Report-Only: o navegador só avisa no console o que bloquearia, sem quebrar nada. Ajuste e depois ative.

Outros cabeçalhos curtos

X-Content-Type-Options: nosniff
Referrer-Policy: strict-origin-when-cross-origin
Permissions-Policy: camera=(), microphone=(), geolocation=()

Scripts de CDN: SRI

Se o CDN for invadido, o script que você carrega de lá muda. O atributo integrity guarda o hash do arquivo, e o navegador recusa qualquer versão diferente: 

<script src="https://cdn.jsdelivr.net/npm/js-yaml@4.1.0/dist/js-yaml.min.js"
  integrity="sha384-..." crossorigin="anonymous"></script>

Redirecionamento aberto

Páginas de login costumam ter ?volta=/minha-conta para voltar depois de entrar (este site tem). Se o servidor redirecionar para qualquer endereço, um golpista manda o link seu-site.com/login?volta=https://site-falso.com: a pessoa vê o seu domínio, entra, e cai numa cópia falsa. A regra: só aceite caminhos internos, que começam com / (e não com //, que o navegador lê como outro domínio).

Dica

O site securityheaders.com analisa os cabeçalhos de qualquer endereço e dá uma nota. Em hospedagens estáticas como o GitHub Pages, não dá para configurar cabeçalhos; aí a CSP pode ir numa <meta http-equiv="Content-Security-Policy">, com algumas limitações (o frame-ancestors, por exemplo, não funciona nela).

Teste o que aprendeu

  1. Como a CSP ajuda contra o XSS?

  2. O que o atributo integrity num <script> garante?

  3. Qual valor de ?volta= é seguro aceitar?
