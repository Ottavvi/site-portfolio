XSS: quando texto vira código

Aula · 12 min

No XSS (cross-site scripting), o atacante consegue rodar JavaScript no seu site, no navegador de outras pessoas. Com isso, ele lê o que a pessoa vê, faz pedidos em nome dela e rouba tokens guardados no localStorage.

Como acontece

O caminho clássico: um texto que veio do usuário (um comentário, um nome, um parâmetro da URL) é colocado na página com innerHTML. Se o texto tiver HTML, ele vira HTML: 

<div id="comentarios"></div>
<script>
  const comentario = 'Ótima pousada! <img src="x" onerror="console.log(\'XSS: eu rodei\')">';

  // Perigoso: o texto vira HTML, e o onerror roda
  document.getElementById('comentarios').innerHTML = '<p>' + comentario + '</p>';
</script>

Repare no console: o código "do comentário" rodou. Num site real, em vez do console.log, estaria um fetch mandando os dados da pessoa para outro lugar.

A correção: texto é texto

<div id="comentarios"></div>
<script>
  const comentario = 'Ótima pousada! <img src="x" onerror="console.log(\'XSS: eu rodei\')">';

  const p = document.createElement('p');
  p.textContent = comentario;   // as tags aparecem como texto, nada roda
  document.getElementById('comentarios').append(p);
</script>
  • Use textContent (ou innerText) para colocar texto. É a regra que resolve a maioria dos casos.
  • Se precisar montar HTML com texto do usuário dentro, escape os caracteres especiais: & vira &amp;, < vira &lt;, > vira &gt;, " vira &quot; e ' vira &#39;.
  • Se o usuário precisa mandar HTML (um editor de texto rico), use uma biblioteca de limpeza testada, como o DOMPurify. Nunca uma regex feita em casa.
  • React, Vue e companhia escapam sozinhos o que vai entre chaves. O perigo volta com dangerouslySetInnerHTML e v-html.

Links também

Um link com endereço vindo do usuário pode ser javascript:alert(1): o código roda no clique. Antes de usar um endereço externo num href, confira se o protocolo é http: ou https:: 

<script>
  function linkSeguro(endereco) {
    try {
      const url = new URL(endereco);
      return ['http:', 'https:'].includes(url.protocol);
    } catch {
      return false;
    }
  }
  for (const e of ['https://instagram.com/pousada', 'javascript:alert(1)', 'JaVaScRiPt:alert(1)', 'data:text/html,oi']) {
    console.log(e, linkSeguro(e));
  }
</script>
Dica

O XSS também aparece com eval, new Function, setTimeout com texto, document.write e atributos como onclick montados com texto. Procure esses nomes no seu código de vez em quando.

  2. Por que um link com href vindo do usuário pode ser perigoso?

  3. O usuário precisa enviar HTML formatado. O que usar?
