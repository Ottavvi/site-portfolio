Senhas, sessões e cookies

Aula · 13 min

Nunca guarde a senha

O banco guarda um hash da senha: o resultado de uma função de mão única, que transforma "minhasenha" num texto que não dá para desfazer. No login, calcula-se o hash do que foi digitado e compara-se com o guardado. Se o banco vazar, as senhas não vazam junto.

  • Use funções feitas para senhas, que são lentas de propósito: Argon2, bcrypt ou scrypt. SHA-256 sozinho é rápido demais: uma placa de vídeo testa bilhões de senhas por segundo.
  • Elas já embutem um sal: um valor aleatório diferente para cada usuário, que faz duas pessoas com a mesma senha terem hashes diferentes. 
import bcrypt from 'bcrypt';

const hash = await bcrypt.hash(senha, 12);        // no cadastro (12 = custo)
const confere = await bcrypt.compare(tentativa, hash); // no login

O login

  • Mensagem genérica: "e-mail ou senha incorretos", sempre. "E-mail não cadastrado" ensina ao atacante quais e-mails existem.
  • Limite de tentativas por conta e por IP (por exemplo, 5 por minuto), com espera crescente.
  • Senhas: exija tamanho (12 ou mais) em vez de regras de símbolos, e recuse as que já vazaram (o serviço Have I Been Pwned tem uma API para isso).
  • Dois fatores (aplicativo autenticador ou chave de segurança) para contas importantes. SMS é melhor que nada, mas é o fator mais fraco.
  • Recuperação de senha com link de uso único e prazo curto.

Sessões e cookies

Depois do login, o servidor precisa reconhecer a pessoa a cada pedido. O jeito mais seguro no navegador é um cookie de sessão com os atributos certos: 

Set-Cookie: sessao=8f3a...; HttpOnly; Secure; SameSite=Lax; Path=/; Max-Age=86400
  • HttpOnly: o JavaScript não lê o cookie, então um XSS não consegue roubá-lo.
  • Secure: só viaja por HTTPS.
  • SameSite=Lax: o cookie não vai em pedidos disparados por outros sites, o que bloqueia a maior parte do CSRF (um site malicioso fazendo você, logado, enviar um formulário para o seu banco).
Dica

Guardar o token de acesso no localStorage é comum, mas qualquer XSS lê o localStorage. Se usar, seja ainda mais rigoroso com o XSS e use tokens de vida curta.
