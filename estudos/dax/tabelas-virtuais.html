Tabelas virtuais e consultas DAX

Aula · 13 min

Muitas funções DAX devolvem uma tabela em vez de um número. Dentro de uma medida, essa tabela existe só durante o cálculo (uma tabela virtual) e serve para responder perguntas que uma soma simples não responde.

Contar o que passa num critério

// Quantos vendedores venderam mais de R$ 250 no período filtrado?
Vendedores acima de 250 =
COUNTROWS(
    FILTER(VALUES(fVendas[Vendedor]), [Faturamento] > 250)
)

// Quantos dias tiveram venda?
Dias com venda = COUNTROWS(FILTER(VALUES(dCalendario[Date]), [Vendas] > 0))

VALUES(coluna) é a lista de valores distintos no contexto atual; FILTER fica com os que passam no teste, e cada [Faturamento] lá dentro é calculado para aquele vendedor (transição de contexto).

Montar uma tabela com colunas calculadas

// Ticket médio do melhor mês
Ticket do melhor mês =
VAR PorMes =
    ADDCOLUMNS(
        VALUES(dCalendario[Ano-Mês]),
        "@Fat", [Faturamento],
        "@Ticket", [Ticket médio]
    )
VAR Melhor = TOPN(1, PorMes, [@Fat], DESC)
RETURN MAXX(Melhor, [@Ticket])

O prefixo @ é uma convenção para colunas de tabelas virtuais, para não confundir com medidas. Para agrupar por colunas de tabelas diferentes, use SUMMARIZE(fVendas, dProduto[Categoria], dCalendario[Ano]) e acrescente os cálculos com ADDCOLUMNS.

A exibição de consulta DAX

No Power BI Desktop, a exibição de consulta DAX (na barra da esquerda) roda consultas que devolvem tabelas, ótima para conferir uma tabela virtual antes de usá-la numa medida: 

EVALUATE
ADDCOLUMNS(
    VALUES(fVendas[Vendedor]),
    "Faturamento", [Faturamento],
    "Posição", RANKX(ALL(fVendas[Vendedor]), [Faturamento])
)
ORDER BY [Faturamento] DESC
Dica

Monte medidas complicadas por partes, com VAR, e use a exibição de consulta para ver o conteúdo de cada variável (devolva ela no RETURN ou rode num EVALUATE). Depurar DAX "no escuro" é o que torna a linguagem difícil.
