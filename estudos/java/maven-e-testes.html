Maven, exceções e JUnit

Aula · 13 min

Maven

Projetos reais usam um gerenciador de build: o Maven ou o Gradle. Eles baixam bibliotecas, compilam, testam e empacotam. 

src/
  main/java/br/com/loja/App.java
  test/java/br/com/loja/AppTest.java
pom.xml
<!-- pom.xml: dependências -->
<dependencies>
  <dependency>
    <groupId>org.junit.jupiter</groupId>
    <artifactId>junit-jupiter</artifactId>
    <version>5.11.0</version>
    <scope>test</scope>
  </dependency>
</dependencies>
mvn test        # roda os testes
mvn package     # gera o .jar em target/
java -jar target/loja-1.0.jar

Os pacotes (br.com.loja) seguem o domínio ao contrário e viram pastas.

Exceções

try (var leitor = Files.newBufferedReader(Path.of("dados.csv"))) {   // fecha sozinho no fim
    String linha;
    while ((linha = leitor.readLine()) != null) processar(linha);
} catch (IOException e) {
    System.err.println("Falha ao ler: " + e.getMessage());
}

Exceções verificadas (como IOException) precisam ser tratadas ou declaradas com throws; o compilador obriga. As não verificadas (RuntimeException e filhas, como IllegalArgumentException) indicam erro de programação ou de regra. O try (...) com recurso fecha o arquivo mesmo se der erro.

JUnit 5

class ContaTest {
    @Test
    void depositoSomaAoSaldo() {
        var conta = new Conta("Ana");
        conta.depositar(new BigDecimal("100"));
        assertEquals(new BigDecimal("100"), conta.getSaldo());
    }

    @ParameterizedTest
    @ValueSource(strings = {"0", "-5"})
    void depositoInvalidoLancaErro(String valor) {
        var conta = new Conta("Ana");
        assertThrows(IllegalArgumentException.class, () -> conta.depositar(new BigDecimal(valor)));
    }
}
