Por que dividir em módulos

Aula · 9 min

Quando um site cresce, um único app.js com mil linhas vira um problema: tudo enxerga tudo, uma variável total de um lado sobrescreve a total do outro, e ninguém sabe de onde vem cada função. Os módulos resolvem isso: cada arquivo tem o seu próprio escopo e diz explicitamente o que exporta e o que importa.

Os arquivos desta trilha

Nesta trilha, o editor finge que existem vários arquivos. A primeira parte é a página HTML, e cada linha // --- nome.js --- começa um arquivo novo: 

<p id="saida"></p>
<script type="module" src="./main.js"></script>

// --- matematica.js ---
export function somar(a, b) {
  return a + b;
}

export const PI = 3.14159;

// --- main.js ---
import { somar, PI } from './matematica.js';

document.querySelector('#saida').textContent = `2 + 3 = ${somar(2, 3)} e PI vale ${PI}`;

As três regras básicas

  • O script precisa de type="module". Sem isso, o navegador não aceita import.
  • export na frente de uma função, classe ou variável deixa ela disponível para outros arquivos. O que não é exportado fica privado.
  • import { nome } from './arquivo.js' traz o que foi exportado. O caminho começa com ./ (ou ../) e termina com .js: no navegador, não dá para omitir a extensão.
Dica

Abrir um index.html com módulos direto do disco (file://) não funciona: o navegador bloqueia. Use um servidor local, como npx serve . ou a extensão Live Server do VS Code.

O que fica privado

<p id="saida"></p>
<script type="module" src="./main.js"></script>

// --- contador.js ---
let valor = 0; // não exportado: ninguém de fora consegue mexer direto

export function incrementar() {
  valor++;
  return valor;
}

// --- main.js ---
import { incrementar } from './contador.js';

incrementar();
incrementar();
document.querySelector('#saida').textContent = 'Contador: ' + incrementar();
console.log(typeof valor); // "undefined": a variável é privada do módulo
