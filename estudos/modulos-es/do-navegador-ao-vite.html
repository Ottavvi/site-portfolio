Do navegador ao Vite

Aula · 10 min

Tudo nesta trilha funciona no navegador sem ferramenta nenhuma, e isso basta para muitos sites (este portfólio é assim). Um bundler como o Vite passa a valer a pena quando:

  • você quer usar muitos pacotes do npm com import x from 'nome-do-pacote';
  • usa JSX, TypeScript ou outra coisa que o navegador não entende direto;
  • o site tem dezenas de módulos e o número de arquivos baixados começa a pesar.

O que o Vite faz

npm create vite@latest meu-site -- --template vanilla
cd meu-site
npm install
npm run dev       # servidor que recarrega na hora a cada arquivo salvo
npm run build     # gera a pasta dist/ otimizada para publicar
  • Em desenvolvimento, ele serve os seus módulos quase como estão (rápido), resolvendo os nomes de pacotes.
  • No build, ele junta os módulos em poucos arquivos, minifica, cria nomes com hash para o cache (main-4f2a.js) e separa os import() dinâmicos em arquivos próprios.
  • Tree shaking: o que um pacote exporta mas você não importa fica de fora. Por isso import { debounce } from 'lodash-es' é bem menor que importar a biblioteca inteira.

Variáveis de ambiente

O Vite coloca em import.meta.env as variáveis dos arquivos .env que começam com VITE_: 

# .env.production
VITE_API_URL=https://api.meusite.com

// em qualquer módulo
const resposta = await fetch(`${import.meta.env.VITE_API_URL}/produtos`);
if (import.meta.env.DEV) console.log('modo de desenvolvimento');
Dica

Tudo o que vai para o front-end é público: qualquer pessoa vê no navegador. Nunca coloque uma chave secreta numa variável VITE_, mesmo que ela esteja num .env.

CommonJS ainda existe

Você vai encontrar require() e module.exports em pacotes antigos e em código Node. Bundlers e o Node convertem entre os dois formatos, mas misturar no mesmo arquivo não funciona. Em código novo, use sempre import/export.
