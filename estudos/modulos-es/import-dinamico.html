import() e import maps

Aula · 12 min

import(): carregar quando precisar

O import normal carrega tudo antes de a página começar. Mas um editor de imagens, um gráfico pesado ou a tela de administração não precisam ser baixados por quem nunca vai usá-los. import('./arquivo.js') carrega o módulo na hora e devolve uma Promise com as exportações: 

<button id="abrir">Mostrar relatório</button>
<div id="area"></div>
<script type="module" src="./main.js"></script>

// --- relatorio.js ---
console.log('relatorio.js foi baixado agora');
export function desenhar(elemento) {
  elemento.innerHTML = '<h2>Relatório</h2><p>Vendas do mês: 42</p>';
}

// --- main.js ---
document.querySelector('#abrir').addEventListener('click', async () => {
  const { desenhar } = await import('./relatorio.js');
  desenhar(document.querySelector('#area'));
});

Abra o console e clique: a mensagem só aparece no clique. Clicar de novo não baixa outra vez, porque o módulo fica guardado.

Dica

Ferramentas como o Vite fazem isso automaticamente: cada import() vira um arquivo separado no build ("code splitting").

Import maps: bibliotecas pelo nome

Em projetos com npm, escrevemos import confetti from 'canvas-confetti'. No navegador puro, um nome sem caminho não significa nada... a menos que um import map diga para onde ele aponta: 

<script type="importmap">
{
  "imports": {
    "dayjs": "https://cdn.jsdelivr.net/npm/dayjs@1.11.13/+esm"
  }
}
</script>

<script type="module">
  import dayjs from 'dayjs';
  console.log(dayjs().format('DD/MM/YYYY'));
</script>

O import map precisa vir antes de qualquer módulo. Fixe sempre a versão exata da biblioteca na URL, para uma atualização não quebrar o site sem aviso.

Pré-carregar

Num site com muitos módulos, o navegador só descobre que main.js importa api.js depois de baixar main.js. <link rel="modulepreload" href="api.js"> no <head> avisa antes, e os downloads acontecem em paralelo.
