Dados de fora: unknown e validação

Aula · 13 min

O limite dos tipos

Os tipos somem no JavaScript gerado. Se você escreve const pedido: Pedido = await resposta.json(), o TypeScript acredita em você, mas nada confere se a API mandou mesmo um pedido. Se ela mudar, o erro aparece longe dali.

unknown

unknown é o oposto seguro do any: aceita qualquer valor, mas não deixa usar nada até você conferir o que é. É o tipo certo para tudo que vem de fora (JSON, localStorage, mensagens): 

const vindo: unknown = JSON.parse('{"id": 1, "total": 99.9}');

console.log(vindo.total); // erro: não sabemos o que é

if (typeof vindo === 'object' && vindo !== null && 'total' in vindo && typeof vindo.total === 'number') {
  console.log(vindo.total.toFixed(2)); // agora pode
}

Type guard: uma função que prova o tipo

Uma função com retorno x is Tipo ensina o TypeScript: se ela devolver true, o valor é daquele tipo dali em diante. 

interface Pedido { id: number; total: number }

function ehPedido(x: unknown): x is Pedido {
  return (
    typeof x === 'object' && x !== null &&
    typeof (x as Pedido).id === 'number' &&
    typeof (x as Pedido).total === 'number'
  );
}

const dados: unknown = JSON.parse('[{"id":1,"total":10},{"id":"2"}]');
const pedidos = Array.isArray(dados) ? dados.filter(ehPedido) : [];
console.log(pedidos); // Pedido[]: só o que passou na checagem

Em projetos maiores, bibliotecas como o Zod fazem isso de forma declarativa: você descreve o formato uma vez e ganha a validação e o tipo juntos.

as const e satisfies

// as const: o valor vira literal e somente leitura
const FRETES = ['normal', 'expresso', 'retirada'] as const;
type Frete = (typeof FRETES)[number];   // 'normal' | 'expresso' | 'retirada'

// satisfies: confere o formato sem perder o tipo exato
const cores = {
  primaria: '#0b7a6f',
  erro: '#b42318'
} satisfies Record<string, string>;
cores.primaria.toUpperCase(); // ok: o TS sabe que primaria existe

const f: Frete = 'retirada';
console.log(FRETES, f);
Dica

O as (como em x as Pedido) não converte nada: só manda o compilador acreditar. Use o mínimo possível, e de preferência dentro de uma função de checagem, como no ehPedido.
