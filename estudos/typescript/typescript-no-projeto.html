TypeScript num projeto de verdade

Aula · 11 min

Instalar e configurar

npm install --save-dev typescript
npx tsc --init          # cria o tsconfig.json

O tsconfig.json diz como compilar. As opções que mais importam:

{
  "compilerOptions": {
    "target": "ES2022",          // qual JavaScript gerar
    "module": "ESNext",          // import/export
    "moduleResolution": "Bundler",
    "strict": true,              // liga todas as checagens importantes
    "noUncheckedIndexedAccess": true, // lista[0] pode ser undefined
    "outDir": "dist"
  },
  "include": ["src"]
}
Dica

Comece projetos novos com "strict": true. Ligar depois, num projeto grande, gera centenas de erros de uma vez.

Quem compila

  • tsc: confere os tipos e gera o JavaScript. npx tsc --noEmit só confere, ótimo para rodar no GitHub Actions.
  • Vite (e esbuild, swc): apagam os tipos muito rápido, sem conferir. Por isso, num projeto com Vite, rode o tsc --noEmit à parte (o template npm create vite@latest com TypeScript já faz isso no npm run build).
  • Node: as versões recentes já rodam arquivos .ts diretamente, também só apagando os tipos.

Módulos e tipos

// tipos.ts
export interface Produto { id: number; nome: string; preco: number }

// carrinho.ts
import type { Produto } from './tipos';  // "import type" some no JavaScript gerado
export function total(itens: Produto[]) { /* ... */ }

Bibliotecas

A maioria das bibliotecas já vem com tipos. As antigas, escritas em JavaScript, costumam ter os tipos num pacote separado mantido pela comunidade: npm install --save-dev @types/nome-da-biblioteca. Os arquivos .d.ts só têm declarações de tipo, sem código.

Sem trocar de linguagem

Num projeto em JavaScript, dá para ganhar boa parte da checagem sem converter nada: ponha // @ts-check no topo do arquivo e descreva os tipos em comentários JSDoc. O VS Code passa a apontar os erros. 

// @ts-check

/**
 * @param {number} preco
 * @param {number} quantidade
 * @returns {number}
 */
function total(preco, quantidade) {
  return preco * quantidade;
}
