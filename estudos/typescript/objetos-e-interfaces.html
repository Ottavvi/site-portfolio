Objetos, interfaces e uniões de valores

Aula · 12 min

O formato de um objeto

Uma interface descreve as propriedades que um objeto tem e o tipo de cada uma:

interface Produto {
  id: number;
  nome: string;
  preco: number;
  descricao?: string;     // opcional: pode faltar
  readonly sku: string;   // só leitura depois de criado
}

const cafe: Produto = { id: 1, nome: 'Café 1kg', preco: 62.9, sku: 'CAF-1' };
cafe.preco = 59.9;   // ok
cafe.sku = 'outro';  // erro: readonly

const caneca: Produto = { id: 2, nome: 'Caneca' }; // erro: faltam preco e sku
console.log(cafe.descricao?.toUpperCase() ?? 'sem descrição');

Propriedade opcional pode ser undefined. O TypeScript obriga você a tratar isso antes de usar, por exemplo com ?. e ??, e assim evita o clássico "Cannot read properties of undefined".

type

O type dá um nome a qualquer tipo. Para objetos, faz quase o mesmo que a interface; a diferença é que ele também serve para uniões e outras combinações: 

type Id = number | string;      // união: um OU outro
type Ponto = { x: number; y: number };

function mostrar(id: Id) {
  console.log('Id:', id);
}
mostrar(10);
mostrar('A-10');
mostrar(true); // erro

Tipos literais

Um tipo pode ser um valor exato. Unir alguns deles cria uma lista fechada de opções, e o editor completa e confere sozinho: 

type Status = 'pendente' | 'pago' | 'enviado' | 'cancelado';

interface Pedido {
  id: number;
  status: Status;
  itens: { produtoId: number; quantidade: number }[];
}

const pedido: Pedido = { id: 1, status: 'pago', itens: [{ produtoId: 3, quantidade: 2 }] };
pedido.status = 'entregue'; // erro: não está na lista
console.log(pedido);
Dica

Interface ou type para objetos? Tanto faz na maior parte das vezes. Uma convenção comum: interface para o formato de objetos, type para uniões e o resto. O importante é manter um padrão no projeto.
