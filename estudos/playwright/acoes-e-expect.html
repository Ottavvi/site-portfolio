Ações e verificações

Aula · 12 min

Ações

  • click(), fill('texto') (apaga e digita), press('Enter')
  • check() e uncheck() para caixas de seleção
  • selectOption('valor') para <select>

Antes de cada ação, o Playwright espera sozinho o elemento existir, estar visível e habilitado. Não precisa de "esperar 2 segundos".

Verificações que esperam

As asserções sobre a página (toBeVisible, toHaveText, toHaveCount...) também tentam de novo até um tempo limite. Se a página leva meio segundo para mostrar o resultado, o teste espera: 

<label for="cep">CEP</label>
<input id="cep">
<button type="button" id="buscar">Buscar</button>
<p id="resultado" role="status"></p>

<script>
  document.querySelector('#buscar').addEventListener('click', () => {
    const cep = document.querySelector('#cep').value;
    document.querySelector('#resultado').textContent = 'Buscando…';
    setTimeout(() => {
      document.querySelector('#resultado').textContent =
        cep === '80010-000' ? 'Curitiba - PR' : 'CEP não encontrado';
    }, 400);
  });
</script>

// --- cep.spec.js ---
import { test, expect } from '@playwright/test';

test('acha a cidade do CEP', async ({ page }) => {
  await page.getByLabel('CEP').fill('80010-000');
  await page.getByRole('button', { name: 'Buscar' }).click();
  await expect(page.getByRole('status')).toHaveText('Curitiba - PR');
});

test('avisa quando o CEP não existe', async ({ page }) => {
  await page.getByLabel('CEP').fill('00000-000');
  await page.getByRole('button', { name: 'Buscar' }).click();
  await expect(page.getByRole('status')).toHaveText('CEP não encontrado');
  await expect(page.getByText('Curitiba')).not.toBeVisible();
});

As verificações mais usadas: toBeVisible, toHaveText (texto inteiro) e toContainText (um pedaço), toHaveValue, toHaveCount, toBeChecked, toBeDisabled, toHaveURL e toHaveTitle. Qualquer uma pode ser negada com .not.

Dica

Evite await page.waitForTimeout(2000). Ele deixa o teste lento quando a página é rápida e falha quando ela é lenta. Verifique o resultado esperado e deixe o Playwright esperar por ele.

Um bom teste

  • Testa um comportamento, com um nome que diz qual ("avisa quando o CEP não existe").
  • Segue o roteiro preparar, agir, conferir.
  • Confere o que a pessoa vê (texto, mensagem, contador), não detalhes internos.
  • Testa também o caminho do erro: é lá que os bugs moram.

Teste o que aprendeu

  1. Por que não usar waitForTimeout(2000)?

  2. Qual a diferença entre toHaveText e toContainText?

  3. Como conferir que algo NÃO aparece?
