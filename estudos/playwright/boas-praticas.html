Testes confiáveis

Aula · 13 min

Cada teste por si

No Playwright de verdade, cada teste recebe uma aba nova, com cookies e localStorage zerados. Um teste nunca deve depender de outro ter rodado antes: assim eles podem rodar em paralelo, em qualquer ordem, e uma falha não derruba as outras. O que se repete no começo de todos vai num beforeEach: 

test.beforeEach(async ({ page }) => {
  await page.goto('/loja');
  await page.getByRole('button', { name: 'Aceitar cookies' }).click();
});
Dica

No editor desta trilha, os testes rodam um depois do outro na mesma página. Por isso, nos exemplos, o beforeEach põe a página no estado inicial (clicando em "Limpar", por exemplo).

Login uma vez só

Fazer login pela tela em cada teste é lento. O Playwright permite logar uma vez num passo de preparação, salvar o estado (cookies e localStorage) num arquivo e reaproveitar em todos os testes com storageState no playwright.config.js.

Simular a rede

Testes que dependem de uma API real ficam lentos e falham quando ela está fora do ar. page.route intercepta pedidos e responde o que você quiser, inclusive erros: 

test('mostra aviso quando a API falha', async ({ page }) => {
  await page.route('**/api/produtos', rota => rota.fulfill({ status: 500 }));
  await page.goto('/loja');
  await expect(page.getByRole('alert')).toHaveText('Não foi possível carregar os produtos');
});

test('lista os produtos da API', async ({ page }) => {
  await page.route('**/api/produtos', rota =>
    rota.fulfill({ json: [{ id: 1, nome: 'Café', preco: 62.9 }] })
  );
  await page.goto('/loja');
  await expect(page.getByRole('listitem')).toHaveCount(1);
});

No CI

O npm init playwright já oferece criar um workflow do GitHub Actions que roda os testes a cada push. O webServer do config sobe o site antes dos testes: 

// playwright.config.js
export default defineConfig({
  use: { baseURL: 'http://localhost:4173', trace: 'on-first-retry' },
  retries: process.env.CI ? 2 : 0,
  webServer: { command: 'npm run preview', port: 4173 }
});

Com trace ligado, uma falha no CI gera um arquivo que o trace viewer (npx playwright show-trace) abre com cada passo, o DOM, o console e a rede naquele momento: dá para depurar uma falha que só acontece lá.

Testes que pegam bugs

Um teste que nunca falha não protege nada. Um jeito simples de saber se os seus testes valem: quebre o código de propósito (troque um + por -, apague uma linha) e veja se algum teste falha. Se nenhum falhar, falta um teste. O próximo desafio faz exatamente isso com os seus testes.
