HTTP: pedido e resposta

Aula · 11 min

Toda vez que o navegador abre uma página, carrega uma imagem ou envia um formulário, ele manda um pedido HTTP para um servidor e recebe uma resposta. Uma API é um servidor que, em vez de páginas, responde dados (quase sempre em JSON) para outros programas usarem: o app do banco, o painel de vendas, o seu front-end.

O pedido

GET /posts/1 HTTP/1.1
Host: jsonplaceholder.typicode.com
Accept: application/json

Um pedido tem um método (o que fazer), um caminho (em quê), cabeçalhos (informações extras) e, às vezes, um corpo (os dados enviados).

  • GET: buscar. Não muda nada no servidor.
  • POST: criar algo novo (um pedido, um cadastro).
  • PUT e PATCH: substituir inteiro ou alterar uma parte.
  • DELETE: apagar.

A resposta

HTTP/1.1 200 OK
Content-Type: application/json; charset=utf-8

{ "userId": 1, "id": 1, "title": "sunt aut facere..." }

O código de status diz como foi, pela casa da centena:

  • 2xx, deu certo: 200 OK, 201 Created (criado), 204 No Content (certo, sem corpo).
  • 3xx, vá para outro lugar: 301 e 302 redirecionam, 304 diz "use o que você já tem em cache".
  • 4xx, o erro é de quem pediu: 400 pedido malformado, 401 não autenticado, 403 sem permissão, 404 não existe, 422 dados inválidos, 429 pedidos demais.
  • 5xx, o erro é do servidor: 500 erro interno, 502 e 503 servidor fora ou sobrecarregado.

Experimente

O fetch faz o pedido pelo JavaScript. Abra o resultado e veja no console o status, um cabeçalho e os dados: 

<script>
  fetch('https://jsonplaceholder.typicode.com/posts/1')
    .then(resposta => {
      console.log('Status:', resposta.status, resposta.ok);
      console.log('Tipo:', resposta.headers.get('content-type'));
      return resposta.json();
    })
    .then(post => console.log('Título:', post.title));
</script>
Dica

Na aba Rede (Network) das ferramentas do navegador (F12), cada pedido aparece com método, status, cabeçalhos e corpo. É a primeira coisa a olhar quando uma integração não funciona.

Teste o que aprendeu

  1. Qual método se usa para criar um cadastro novo?

  2. A API respondeu 404. De quem é o problema?

  3. O que o status 401 indica?
