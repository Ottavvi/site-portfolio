Chamadas resilientes

Aula · 13 min

Redes falham, servidores ficam lentos e APIs limitam quantos pedidos você pode fazer. Código de produção espera por isso.

Tentar de novo, com calma

Erros passageiros (falha de rede, 502, 503, 429) muitas vezes somem na segunda tentativa. A técnica padrão é o recuo exponencial: esperar 0,5 s, depois 1 s, depois 2 s, para não piorar um servidor que já está sobrecarregado. 

<script>
  const esperar = ms => new Promise(r => setTimeout(r, ms));

  async function comRetentativas(funcao, tentativas = 3) {
    for (let i = 1; ; i++) {
      try {
        return await funcao();
      } catch (erro) {
        if (i >= tentativas) throw erro;
        const ms = 500 * 2 ** (i - 1);
        console.log(`Tentativa ${i} falhou (${erro.message}). Esperando ${ms} ms...`);
        await esperar(ms);
      }
    }
  }

  // Uma função que falha duas vezes e depois funciona
  let vezes = 0;
  comRetentativas(async () => {
    vezes++;
    if (vezes < 3) throw new Error('rede instável');
    return 'deu certo na tentativa ' + vezes;
  }).then(console.log);
</script>
  • Não repita erros que não vão mudar: 400, 401, 403, 404 e 422 continuarão iguais.
  • Com 429 (pedidos demais), respeite o cabeçalho Retry-After, que diz quantos segundos esperar.
  • Lembre da idempotência: repetir um POST pode duplicar o pedido.

Em paralelo

Pedidos independentes não precisam esperar um pelo outro. Promise.all dispara todos e espera o conjunto; Promise.allSettled espera todos mesmo que algum falhe: 

<script>
  const base = 'https://jsonplaceholder.typicode.com';
  const inicio = performance.now();
  Promise.all([
    fetch(base + '/users/1').then(r => r.json()),
    fetch(base + '/posts?userId=1').then(r => r.json()),
    fetch(base + '/todos?userId=1').then(r => r.json())
  ]).then(([usuario, posts, tarefas]) => {
    console.log(usuario.name, '·', posts.length, 'posts ·', tarefas.length, 'tarefas');
    console.log('Tempo:', Math.round(performance.now() - inicio), 'ms');
  });
</script>

Não pedir o que você já tem

Um Map guardando as respostas por URL evita repetir pedidos iguais (por exemplo, abrir o mesmo produto duas vezes). Guarde a Promise, não o resultado: assim dois pedidos simultâneos para a mesma URL viram um só. 

const cache = new Map();
function buscarComCache(url) {
  if (!cache.has(url)) cache.set(url, fetch(url).then(r => r.json()));
  return cache.get(url);
}
Dica

Numa busca enquanto a pessoa digita, combine debounce (espera ela parar de digitar) com AbortController (cancela o pedido anterior). Senão, a resposta de "caf" pode chegar depois da de "café" e mostrar o resultado errado.

Teste o que aprendeu

  1. Qual erro vale a pena tentar de novo?

  2. O que é recuo exponencial?

  3. Por que o cache guarda a Promise, e não o resultado?
