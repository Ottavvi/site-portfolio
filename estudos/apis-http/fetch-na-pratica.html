fetch na prática: erros e envio de dados

Aula · 13 min

A pegadinha do fetch

O fetch só rejeita a Promise quando a rede falha (sem internet, servidor inalcançável). Um 404 ou um 500 não são erro para ele: a Promise resolve normalmente. Quem confere é você, com resposta.ok (verdadeiro para 200 a 299): 

<script>
  async function buscarJson(url) {
    const resposta = await fetch(url);
    if (!resposta.ok) {
      throw new Error(`A API respondeu ${resposta.status}`);
    }
    return resposta.json();
  }

  buscarJson('https://jsonplaceholder.typicode.com/users/1')
    .then(usuario => console.log('Achei:', usuario.name))
    .catch(erro => console.log('Falhou:', erro.message));

  buscarJson('https://jsonplaceholder.typicode.com/users/9999')
    .then(usuario => console.log('Achei:', usuario.name))
    .catch(erro => console.log('Falhou:', erro.message));
</script>

Enviar dados

Para criar algo, mande o método, o cabeçalho dizendo que o corpo é JSON e o corpo já convertido em texto: 

<script>
  async function criarPost(titulo) {
    const resposta = await fetch('https://jsonplaceholder.typicode.com/posts', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ title: titulo, body: 'Texto', userId: 1 })
    });
    if (!resposta.ok) throw new Error(`Erro ${resposta.status}`);
    return resposta.json();
  }

  criarPost('Meu primeiro POST').then(criado => console.log('Criado com id', criado.id));
</script>
Dica

Esquecer o JSON.stringify envia o texto "[object Object]". Esquecer o Content-Type faz muitos servidores não entenderem o corpo. São os dois erros mais comuns em POST.

Mostrar o que está acontecendo

Pedidos demoram. Uma boa interface mostra três estados: carregando, erro (com uma mensagem útil e, se possível, um botão para tentar de novo) e pronto. E desabilita o botão de enviar enquanto espera, para a pessoa não mandar o mesmo pedido duas vezes.

Tempo limite

Por padrão, um pedido pode ficar esperando minutos. AbortSignal.timeout desiste depois de um tempo: 

try {
  const resposta = await fetch(url, { signal: AbortSignal.timeout(5000) });
} catch (erro) {
  if (erro.name === 'TimeoutError') console.log('A API demorou demais.');
}

Teste o que aprendeu

  1. A API respondeu 500. O que o fetch faz?

  2. O que falta neste POST: fetch(url, { method: "POST", body: dados })?

  3. Por que desabilitar o botão enquanto o pedido está em andamento?
