Classes, propriedades e records

Aula · 13 min

Em C#, quase tudo vive dentro de uma classe: um molde que junta dados (propriedades) e comportamento (métodos). 

public class Conta
{
    public string Titular { get; }
    public decimal Saldo { get; private set; }   // só a própria classe altera

    public Conta(string titular) => Titular = titular;

    public void Depositar(decimal valor)
    {
        if (valor <= 0) throw new ArgumentException("Valor precisa ser positivo");
        Saldo += valor;
    }

    public bool Sacar(decimal valor)
    {
        if (valor > Saldo) return false;
        Saldo -= valor;
        return true;
    }
}

var conta = new Conta("Ana");
conta.Depositar(200);
conta.Sacar(50);
Console.WriteLine(conta.Saldo); // 150

O private set é o encapsulamento: de fora, dá para ler o saldo, mas não trocar por qualquer valor. Só os métodos, que conferem as regras, mexem nele.

Records: dados imutáveis

public record Produto(string Nome, decimal Preco, string Categoria);

var p = new Produto("Café", 18.5m, "Mercearia");
var promo = p with { Preco = 15m };   // cópia com um campo diferente
Console.WriteLine(p == new Produto("Café", 18.5m, "Mercearia")); // True: compara pelo conteúdo

Um record cria numa linha um tipo com construtor, propriedades só de leitura, comparação por valor e um ToString legível. Ótimo para dados que vêm de um banco ou de uma API.

Interfaces

public interface IFrete { decimal Calcular(decimal peso); }

public class Correios : IFrete { public decimal Calcular(decimal peso) => 15 + peso * 2; }
public class Retirada : IFrete { public decimal Calcular(decimal peso) => 0; }

IFrete frete = new Correios();
Console.WriteLine(frete.Calcular(3)); // 21

Uma interface é um contrato: quem a implementa promete ter aqueles métodos. O código que usa IFrete não precisa saber qual frete é: dá para trocar sem mexer nele.
