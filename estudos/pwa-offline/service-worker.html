O service worker

Aula · 14 min

O service worker é um arquivo JavaScript separado, que roda fora da página: não tem acesso ao DOM, conversa com as páginas por mensagens e pode ser desligado pelo navegador quando não está fazendo nada. O que ele tem de especial são os eventos.

Registrar

// app.js (na página)
if ('serviceWorker' in navigator) {
  window.addEventListener('load', () => {
    navigator.serviceWorker.register('/sw.js');
  });
}

O escopo é a pasta onde o arquivo está: /sw.js controla o site inteiro; /app/sw.js só as páginas dentro de /app/. Por isso ele costuma ficar na raiz.

O ciclo de vida

  1. install: roda uma vez por versão. É a hora de baixar e guardar no cache os arquivos essenciais (o "app shell").
  2. activate: a versão nova assume. É a hora de apagar caches de versões antigas.
  3. fetch: dispara a cada pedido das páginas controladas (HTML, CSS, imagens, chamadas de API). Aqui você decide de onde vem a resposta. 
// sw.js
const VERSAO = 'v3';
const ESSENCIAIS = ['/', '/index.html', '/css/style.css', '/js/app.js', '/offline.html'];

self.addEventListener('install', evento => {
  evento.waitUntil(
    caches.open(VERSAO).then(cache => cache.addAll(ESSENCIAIS))
  );
});

self.addEventListener('activate', evento => {
  evento.waitUntil(
    caches.keys().then(nomes =>
      Promise.all(nomes.filter(nome => nome !== VERSAO).map(nome => caches.delete(nome)))
    )
  );
});

self.addEventListener('fetch', evento => {
  if (evento.request.method !== 'GET') return;     // só GET vai para o cache
  evento.respondWith(
    caches.match(evento.request).then(guardado => guardado ?? fetch(evento.request))
  );
});

waitUntil segura a etapa até a Promise terminar: se o addAll falhar (um arquivo com 404, por exemplo), a instalação falha e a versão antiga continua.

Atualizações

O navegador confere o sw.js a cada navegação. Se qualquer byte mudou, uma versão nova é instalada, mas fica esperando: só assume quando todas as abas com a versão antiga forem fechadas. Isso evita que a página e o service worker fiquem com versões que não combinam. 

// Para assumir na hora (cuidado: a página aberta continua com o JS antigo)
self.addEventListener('install', () => self.skipWaiting());
self.addEventListener('activate', evento => evento.waitUntil(self.clients.claim()));
Dica

O erro mais comum: mudar o CSS e esquecer de mudar a versão no sw.js. O arquivo do service worker continua igual, nenhuma versão nova é instalada, e todo mundo continua vendo o CSS velho do cache. Trocar VERSAO a cada publicação resolve.

Teste o que aprendeu

  1. Em que evento se guardam os arquivos essenciais no cache?

  2. Uma versão nova do service worker foi instalada. Quando ela assume?

  3. O que /js/sw.js consegue controlar?
