Escopo e closures

Aula · 11 min

Escopo

Escopo é a região do código onde uma variável existe. Variáveis criadas com let e const só existem dentro do bloco { } em que nasceram, e nos blocos de dentro dele. 

<script>
  const site = 'Portfólio'; // escopo global: vale em tudo

  function mostrar() {
    const secao = 'Projetos'; // só existe dentro de mostrar
    if (true) {
      const item = 'Pousada'; // só existe dentro do if
      console.log(site, secao, item);
    }
    console.log(typeof item); // "undefined": fora do bloco
  }
  mostrar();
</script>

Escopos pequenos são uma vantagem: menos nomes visíveis ao mesmo tempo significa menos chance de uma parte do código atrapalhar outra.

Closures

Uma função criada dentro de outra continua tendo acesso às variáveis de fora, mesmo depois que a função de fora terminou. Essa "memória" se chama closure. 

<script>
  function criarContador() {
    let valor = 0;
    return {
      somar: () => ++valor,
      zerar: () => (valor = 0)
    };
  }

  const visitas = criarContador();
  const cliques = criarContador();
  visitas.somar();
  visitas.somar();
  cliques.somar();
  console.log(visitas.somar()); // 3
  console.log(cliques.somar()); // 2: cada contador tem o seu valor
</script>

Ninguém de fora consegue mexer em valor diretamente: só pelas funções que o contador devolveu. É um jeito de ter dados privados.

Closures no dia a dia

Você já usou closures sem perceber: toda função passada para addEventListener ou setTimeout lembra das variáveis de onde foi criada. Um caso clássico é o debounce, que só executa uma função quando a pessoa para de digitar: 

<label>Buscar <input id="busca"></label>
<script>
  function debounce(funcao, ms) {
    let espera;
    return (...args) => {
      clearTimeout(espera);
      espera = setTimeout(() => funcao(...args), ms);
    };
  }

  const buscar = debounce(texto => console.log('Buscando por', texto), 400);
  document.querySelector('#busca').addEventListener('input', e => buscar(e.target.value));
</script>
Dica

O laço for (let i = 0; ...) cria um i novo a cada volta, e cada closure guarda o seu. Com o antigo var, todas compartilhavam o mesmo, e esse era um dos bugs mais famosos do JavaScript.
