Delegação de eventos e debounce

Aula · 12 min

Delegação de eventos

Numa lista com 500 itens, pôr um addEventListener em cada botão gasta memória e não funciona para itens criados depois. Como os eventos sobem pela árvore (bubbling), basta um ouvinte no pai e descobrir onde foi o clique com event.target.closest(): 

<ul id="lista">
  <li data-id="1">Café <button data-acao="remover">×</button></li>
  <li data-id="2">Chá <button data-acao="remover">×</button></li>
</ul>
<button id="novo">Adicionar item</button>

<script>
  const lista = document.querySelector('#lista');
  let proximo = 3;

  lista.addEventListener('click', evento => {
    const botao = evento.target.closest('[data-acao="remover"]');
    if (!botao) return;                       // o clique não foi num botão de remover
    botao.closest('li').remove();
  });

  document.querySelector('#novo').addEventListener('click', () => {
    lista.insertAdjacentHTML('beforeend',
      `<li data-id="${proximo}">Item ${proximo++} <button data-acao="remover">×</button></li>`);
  });
</script>

Os itens novos funcionam sem nenhum código extra, porque o ouvinte está na lista, não neles.

Debounce

Uma busca que consulta o servidor a cada tecla dispara 10 pedidos para "cafeteira". Com debounce, a função só roda depois que a pessoa parou de digitar por um tempo: 

<input id="busca" placeholder="Digite rápido...">
<p id="log"></p>

<script>
  function debounce(funcao, espera) {
    let timer;
    return (...argumentos) => {
      clearTimeout(timer);
      timer = setTimeout(() => funcao(...argumentos), espera);
    };
  }

  let chamadas = 0;
  const buscar = debounce(texto => {
    chamadas++;
    document.querySelector('#log').textContent = `Buscou "${texto}" (${chamadas} busca(s) no total)`;
  }, 400);

  document.querySelector('#busca').addEventListener('input', e => buscar(e.target.value));
</script>

Cada tecla cancela o timer anterior e começa outro. Só quando passam 400 ms sem teclas a busca acontece. A função devolvida é um closure: ela lembra a variável timer entre as chamadas.

Dica

O primo do debounce é o throttle: em vez de esperar parar, ele roda no máximo uma vez a cada intervalo. Bom para eventos que disparam sem parar, como scroll e redimensionar a janela.

Medir antes de otimizar

performance.now() mede o tempo com precisão, e a aba Performance das ferramentas de desenvolvedor mostra o que trava a página. Na maioria das vezes, o lento não é o JavaScript, mas mexer no DOM demais: monte os elementos e insira de uma vez (com um DocumentFragment ou replaceChildren), em vez de um por um.
