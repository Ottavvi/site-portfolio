Erros e depuração

Aula · 10 min

Todo código tem erros em algum momento. A diferença entre quem trava e quem resolve está em ler a mensagem e saber investigar.

Os erros mais comuns

  • ReferenceError: x is not defined: você usou um nome que não existe. Quase sempre é erro de digitação ou a variável foi criada em outro escopo.
  • TypeError: Cannot read properties of null: você tentou usar algo que é null ou undefined. Muito comum com querySelector que não achou o elemento.
  • TypeError: x is not a function: você chamou com () algo que não é função.
  • SyntaxError: o código está mal escrito (um parêntese ou chave faltando) e nem começa a rodar. 
<script>
  const botao = document.querySelector('#nao-existe');
  console.log(botao); // null: o seletor não achou nada
  botao.addEventListener('click', () => {}); // TypeError
</script>

Investigando

  • Espalhe console.log para ver o valor das variáveis em cada etapa.
  • Nas ferramentas do navegador (F12), a aba Sources (ou Fontes) permite pausar o código numa linha e ver tudo naquele momento. Escrever debugger; no código faz o mesmo.
  • Reduza o problema: comente partes até descobrir qual linha causa o erro.

try e catch

Alguns erros são esperados: um texto que deveria ser JSON e não é, uma rede que caiu. Com try...catch, o programa trata o erro em vez de parar: 

<script>
  const texto = '{ nome: Ana }'; // JSON inválido: faltam aspas

  try {
    const dados = JSON.parse(texto);
    console.log(dados);
  } catch (erro) {
    console.log('Não consegui ler os dados:', erro.message);
  } finally {
    console.log('O finally roda sempre, com ou sem erro.');
  }
</script>

Lançando os próprios erros

Quando uma função recebe algo que não faz sentido, é melhor avisar com throw do que devolver um resultado errado em silêncio: 

<script>
  function dividir(a, b) {
    if (b === 0) throw new Error('Não dá para dividir por zero.');
    return a / b;
  }

  try {
    console.log(dividir(10, 2));
    console.log(dividir(1, 0));
  } catch (erro) {
    console.log(erro.message);
  }
</script>
Dica

Não use try...catch para esconder erros. Um catch vazio faz o problema sumir da tela e continuar existindo. Trate o erro (mostre uma mensagem, tente de novo) ou deixe ele aparecer.

  2. Quando o bloco finally é executado?
