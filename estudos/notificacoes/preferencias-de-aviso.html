Preferências de aviso

Aula · 11 min

A permissão do navegador é um interruptor só: tudo ou nada. Quem avisa demais leva um "bloquear" e perde o canal para sempre. A saída é dar controle fino dentro do seu app, para a pessoa nunca precisar desligar tudo.

O que oferecer

  • Categorias: pedidos e mensagens sim, promoções não. Cada uma com seu interruptor, e as de marketing desligadas por padrão.
  • Canais: notificação no navegador, e-mail, WhatsApp. A mesma informação não precisa chegar por todos.
  • Horário silencioso: nada entre 22h e 7h, a não ser que seja urgente.
  • Resumo: em vez de 15 avisos de "curtiram sua foto", um por dia com tudo junto.

  </fieldset>

<pre id="salvo"></pre>

<script>
  const form = document.querySelector('#prefs');
  function salvar() {
    const dados = new FormData(form);
    const prefs = {
      categorias: { pedidos: dados.has('pedidos'), mensagens: dados.has('mensagens'), promocoes: dados.has('promocoes') },
      silencio: { inicio: dados.get('inicio'), fim: dados.get('fim') }
    };
    localStorage.setItem('prefs-aviso', JSON.stringify(prefs));
    document.querySelector('#salvo').textContent = JSON.stringify(prefs, null, 2);
  }
  form.addEventListener('change', salvar);
  salvar();
</script>

Num app com conta, essas preferências vão para o servidor, que é quem decide se envia um push ou um e-mail.

Limite de frequência

Mesmo com tudo ligado, ninguém quer 30 avisos por hora. Um limite simples ("no máximo 3 por hora por categoria; o resto entra no próximo resumo") protege a pessoa de um bug ou de uma campanha exagerada.

Dica

Meça: quantas notificações são clicadas e quantas pessoas desligam uma categoria depois de recebê-la. Uma categoria que só é desligada está atrapalhando.

Teste o que aprendeu

  1. Por que oferecer categorias de aviso dentro do app?

  2. Como deve vir a categoria de promoções?

  3. O que é um resumo (digest)?
