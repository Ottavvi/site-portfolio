Core Web Vitals e Lighthouse

Aula · 13 min

O Google mede a experiência real de quem visita com três números, os Core Web Vitals. Eles entram na classificação e, mais importante, se relacionam direto com quanta gente desiste da página.

LCP: a parte principal apareceu?

Largest Contentful Paint: quanto tempo até o maior elemento visível (geralmente a foto de capa ou o título) aparecer. Bom: até 2,5 s.

  • Imagem de capa leve (WebP ou AVIF, no tamanho certo) e com fetchpriority="high".
  • Nunca loading="lazy" na imagem principal: ela esperaria o resto.
  • CSS e fontes que bloqueiam a página: só o essencial, e as fontes com preload.

INP: responde rápido ao toque?

Interaction to Next Paint: o tempo entre um clique (ou toque, ou tecla) e a tela mudar. Bom: até 200 ms.

  • JavaScript pesado rodando no carregamento trava os cliques: carregue com defer e divida o que só é usado depois (import() dinâmico).
  • Em tarefas longas, devolva o controle ao navegador entre as partes (await new Promise(r => setTimeout(r))).

CLS: a página pulou?

Cumulative Layout Shift: o quanto o conteúdo se mexe sozinho enquanto carrega (aquele botão que muda de lugar na hora do clique). Bom: até 0,1.

  • Toda imagem e vídeo com width e height (ou aspect-ratio no CSS): o navegador reserva o espaço antes de baixar.
  • Reserve espaço para anúncios, avisos de cookies e conteúdo que chega depois.
  • Fontes com font-display: swap e tamanhos parecidos com a fonte reserva.
<style>
  body { font-family: system-ui; }
  .caixa { background: #eef2f5; padding: 8px; }
</style>
<p>Sem width/height, o texto abaixo "pula" quando a imagem chega:</p>
<img src="https://picsum.photos/seed/praia/600/300" alt="Praia" style="max-width:100%;height:auto">
<p class="caixa">Este parágrafo desceu quando a imagem carregou.</p>
<p>Com width e height, o espaço já está reservado:</p>
<img src="https://picsum.photos/seed/mar/600/300" alt="Mar" width="600" height="300" style="max-width:100%;height:auto">
<p class="caixa">Este não se mexeu.</p>

Laboratório x campo

  • Laboratório: o Lighthouse (F12 → Lighthouse) simula um celular médio numa rede lenta. Ótimo para achar problemas e comparar antes e depois.
  • Campo: dados reais de visitantes do Chrome (relatório CrUX), mostrados no PageSpeed Insights e no Search Console. É o que o Google usa na classificação. Só aparece para sites com visitas suficientes.
Dica

Este portfólio roda o Lighthouse a cada push no GitHub Actions, com notas mínimas (ferramentas/lighthouserc.json). Se uma mudança deixar o site lento, o commit ganha um X vermelho. A história de como ele ficou três vezes mais rápido está no diário de estudos.
